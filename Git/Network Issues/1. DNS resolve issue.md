## এরর-টা কী ধরনের ছিল?

```
fatal: unable to access 'https://github.com/...': Could not resolve host: github.com
```

Git যখন push করে, প্রথম ধাপ হলো `github.com` নামটাকে একটা IP address-এ (যেমন `20.205.243.166`) অনুবাদ করা — এই অনুবাদের সিস্টেমটার নাম **DNS** (Domain Name System), অনেকটা ফোনবুকের মতো: নাম দিলে নম্বর পাওয়া যায়।

**"Could not resolve host"** মানে: git ফোনবুকে নামটাই খুঁজে পায়নি — অর্থাৎ GitHub পর্যন্ত পৌঁছানোর চেষ্টাই শুরু হয়নি। তাই এটা:

- ❌ Git-এর সমস্যা নয় (git ঠিক আছে)
- ❌ GitHub-এর সমস্যা নয় (আপনার অনুরোধ GitHub পর্যন্ত যায়ইনি)
- ❌ Authentication/permission সমস্যা নয়
- ✅ **আপনার মেশিন → DNS সার্ভার** — এই রাস্তার সমস্যা

## আমি কীভাবে diagnose করলাম — ৩ ধাপের পরীক্ষা

```powershell
# ধাপ ১: DNS resolve হচ্ছে কিনা
nslookup github.com

# ধাপ ২: resolve হলে, সার্ভার পর্যন্ত পৌঁছানো যাচ্ছে কিনা
ping github.com

# ধাপ ৩: ISP-র DNS-কে bypass করে সরাসরি Google-এর DNS দিয়ে চেষ্টা
nslookup github.com 8.8.8.8
```

**ফলাফল পড়ার নিয়ম (decision tree):**

|ধাপ ১ (nslookup)|ধাপ ৩ (nslookup 8.8.8.8)|রোগ নির্ণয়|
|---|---|---|
|✅ IP দিল|—|DNS ঠিক আছে — সমস্যা সাময়িক ছিল, আবার push দিন|
|❌ fail|✅ IP দিল|**আপনার ISP-র DNS সার্ভার নষ্ট** → DNS বদলে 1.1.1.1/8.8.8.8 দিন|
|❌ fail|❌ fail|**ইন্টারনেটই নেই** → WiFi/router/VPN দেখুন|

আপনার ক্ষেত্রে ধাপ ১-এই IP পেয়ে গেলাম — মানে push-এর মুহূর্তে যা হয়েছিল তা ততক্ষণে সেরে গেছে (সাময়িক ISP DNS glitch)। তাই "সমাধান" ছিল স্রেফ **আবার push দেওয়া**।

## পরেরবার নিজে সামলানোর চেকলিস্ট

1. `nslookup github.com` → IP এলে আবার push দিন, শেষ।
2. না এলে `nslookup github.com 8.8.8.8` → এটায় এলে ISP-র DNS-এর দোষ:
    - দ্রুত fix: `ipconfig /flushdns` (পুরনো ভুল cache মোছে)
    - স্থায়ী fix: Settings → Network → DNS Manual → `1.1.1.1` / `8.8.8.8`
3. দুটোই fail → ইন্টারনেট নেই: WiFi reconnect, router restart, VPN off/on।
4. **Bonus টিপ:** এররের শব্দ দেখে ধরন চিনুন —
    - `Could not resolve host` → DNS/নেটওয়ার্ক (আজকেরটা)
    - `Connection timed out / refused` → নেট আছে কিন্তু firewall/proxy আটকাচ্ছে
    - `Authentication failed / 403` → credential/permission সমস্যা
    - `non-fast-forward / rejected` → এটা আসল git সমস্যা (pull করে আবার push)

মূল কথা: **এররের প্রথম লাইনটাই বলে দেয় দোষটা কোন স্তরে** — DNS, নেটওয়ার্ক, auth, নাকি git। স্তরটা চিনলে সমাধান সোজা।
