# 06 · Policy Resolution Logic (at Submit)

> PR submit করার মুহূর্তে system ঠিক করে **কোন Workflow** ব্যবহার হবে। এটাই `ApprovalPolicy`-এর একমাত্র কাজ।

---

## Matching query

```sql
SELECT WorkflowId
FROM ApprovalPolicy
WHERE CurrencyId = @PR_CurrencyId
  AND @PR_TotalPrice >= MinAmount
  AND (MaxAmount IS NULL OR @PR_TotalPrice <= MaxAmount)
  AND IsActive = 1
  AND IsDeleted = 0
```

- **Currency মিলতে হবে** (A3 — কোনো conversion নেই)।
- `MaxAmount IS NULL` মানে **unlimited/infinity**।

---

## Match-এর ফলাফল অনুযায়ী আচরণ

| Result | কী হবে |
|---|---|
| **1 match** | ✅ `match.WorkflowId` নিয়ে PR-এ **snapshot** করা হয়। |
| **0 match** | ❌ **Submit block** + error: *"No approval policy configured for this currency/amount."* |
| **>1 match** | ⚠️ Configuration error। **Source-এ ঠেকানো হবে:** policy save করার সময় একই currency-তে overlapping range validate করে reject করা হবে। |

---

## গুরুত্বপূর্ণ concept: ApprovalPolicy শুধু "router"

ApprovalPolicy আর PRApproval-এর মধ্যে **কোনো direct FK নেই**। পুরো flow:

```
PurchaseRequest
      │  (amount + currency)
      ▼
ApprovalPolicy        ← শুধু বলে "এই amount/currency = Workflow X"
      │  WorkflowId
      ▼
ApprovalWorkflow
      │
      ▼
ApprovalWorkflowStage ← stage-গুলো পড়া হয়
      │
      ▼
PurchaseApproval      ← এখান থেকে approval log চলে
```

ApprovalPolicy-এর কাজ workflow নির্বাচন পর্যন্তই; এরপর পুরো process চালায় Workflow + Stage + PurchaseApproval। বিস্তারিত [09. Key Concepts](<09. Key Concepts Explained.md>)।
