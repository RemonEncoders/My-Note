# 04 · Data Model & ER Diagram

> সব নতুন entity `AuditableEntity` inherit করে → `Id, IsActive, IsDeleted, CreatedBy, Created, LastModifiedBy, LastModified` free। নিচে শুধু **অতিরিক্ত field** দেখানো হলো।

---

## ER Diagram (concept)

```text
        ApplicationRole                     ApplicationUser
              │                                    │
              │ (M:N via ApplicationUserRole)      │
              └──────────────┬─────────────────────┘
                   |         |
     ┌───────────────────────┼────────────────────────────┐
     │                       │                            │
     ▼                       ▼                            ▼
ApprovalWorkflowStage   PurchaseApproval.ApprovedBy   (approver pool)
     ▲   (RoleId FK)          ▲
     │                        │
     │                        │ (StageId, snapshot)
ApprovalWorkflow ────────────┐│
     ▲   (1:M stages)         ││
     │                        ││
     │ (FK, Published only)   ││
ApprovalPolicy                ││
 (Currency + Amount → Workflow)│
                              ││
                     ┌────────┘│
                     │         │
                 Purchase ─────┘  (1:M PurchaseApproval)
              (WorkflowId snapshotted at submit)
```

**সম্পর্কের সারাংশ:**
- `ApprovalWorkflow` **1 : M** `ApprovalWorkflowStage`
- `ApprovalWorkflow` **1 : M** `ApprovalPolicy`
- `ApprovalWorkflow` **1 : M** `Purchase` (snapshot)
- `Purchase` **1 : M** `PurchaseApproval`
- `ApprovalWorkflowStage` **1 : M** `PurchaseApproval`
- `ApplicationUser` **1 : M** `PurchaseApproval` (ApprovedBy)
- `ApprovalPolicy`-এর **PRApproval-এর সাথে সরাসরি FK নেই** — এটা শুধু routing/config table (দেখুন [09](<09. Key Concepts Explained.md>))।

## 4.1 `ApprovalWorkflow`

| Field | Type | Note |
|---|---|---|
| WorkflowName | string | |
| WorkflowStatus | `EnumWorkflowStatus` | Draft → Published → Archived; **Published হলে immutable** |

---

## 4.2 `ApprovalWorkflowStage` — *system-এর heart*

| Field | Type | Note |
|---|---|---|
| WorkflowId | Guid (FK) | |
| StageNo | int | 1,2,3… contiguous |
| RoleId | Guid (FK → `ApplicationRole`) | এই role-এর যেকোনো একজন active user approve করে |
| IsMandatory | bool (default true) | future use (B2) |

---

## 4.3 `ApprovalPolicy` — *mutable, routing layer*

| Field | Type | Note |
|---|---|---|
| CurrencyId | Guid (FK) | **Required** |
| MinAmount | decimal | inclusive |
| MaxAmount | decimal? | **NULL = infinity (unlimited)** |
| WorkflowId | Guid (FK) | একটা Published workflow-এ point করে; clone-এর পর re-point হয় |

---

## 4.4 `PurchaseApproval` — *audit log, row per action (B5)*

| Field | Type | Note |
|---|---|---|
| PurchaseId | Guid (FK) | |
| StageId | Guid (FK → `ApprovalWorkflowStage`) | snapshot |
| StageNo | int | snapshot |
| ApprovedById | Guid (FK → `ApplicationUser`) | |
| Action | `EnumApprovalAction` | Approved / Rejected |
| Remarks | string | |
| ActionDate | DateTime | |
| *RoundNo* | *int* | **OPEN** — resubmit cycle আলাদা করতে (দেখুন [11](<11. Open Items and Future Scope.md>)) |

---

## 4.5 বিদ্যমান `Purchase`-এ পরিবর্তন

| Field | Type | Note |
|---|---|---|
| WorkflowId | Guid? (FK) | **submit-এর সময় snapshot** — এটাই in-flight PR-কে future policy/workflow পরিবর্তন থেকে রক্ষা করে |
| CurrentStageNo | int? | বর্তমান pending stage; শেষ হলে `null` |
| ApprovalStatus | `EnumPRApprovalStatus` | নতুন; existing `Status` অপরিবর্তিত |
| RowVersion | byte[] `[Timestamp]` | B4 concurrency guard |
