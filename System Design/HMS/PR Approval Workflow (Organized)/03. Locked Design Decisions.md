# 03 · Locked Design Decisions

> সব সিদ্ধান্ত চূড়ান্ত (locked)। শুধু §Open items বাদে (দেখুন [11](<11. Open Items and Future Scope.md>))।

---

## 🔴 A. Core decisions

| # | Topic | Decision |
|---|---|---|
| **A1** | Stage কে approve করবে | **Role-based** — stage-এর role-এর **যেকোনো একজন active user** approve করলেই stage complete। |
| **A2** | Self-approval | **Allowed** — creator যদি stage-এর role-এ থাকে, সে নিজের PR approve করতে পারবে। কোনো segregation-of-duties block নেই। *(সজ্ঞান business call)* |
| **A3** | Currency | **Currency `ApprovalPolicy`-তে configure করা হবে (required field)।** কোনো currency conversion নেই। Matching = currency **এবং** amount range। |
| **A4** | Submit-এর পর amount edit | **Draft অবস্থায় free।** Approval শুরু হলে (`PendingApproval`) amount edit **blocked**। |
| **A5** | PR approval states | **আলাদা enum** `EnumPRApprovalStatus`: `Draft → PendingApproval → Approved → Rejected → Cancelled`। Existing `Status` অক্ষত। |
| **A6** | Reject আচরণ | Reject = full **Rejected**। Creator edit করে **resubmit → stage-1 থেকে সম্পূর্ণ নতুন cycle**। |

## 🟡 B. Structural decisions

| # | Topic | Decision |
|---|---|---|
| **B1** | Workflow versioning | **Published হলে Workflow immutable।** পরিবর্তন = পুরো workflow **clone** (পুরনো → Archived, নতুন → Published)। `WorkflowId`-ই version। Stage-level edit নেই। → বিস্তারিত [09](<09. Key Concepts Explained.md>) |
| **B2** | `IsMandatory` on stage | Flag রাখা হবে future-এর জন্য; **এখন সব stage mandatory** (skip/optional logic implement হবে না)। |
| **B3** | Stage-level versioning | **বাদ** — B1 দিয়ে cover হয়ে যায়। Workflow-এর ভেতর `StageNo` সবসময় contiguous (1,2,3)। Engine তবু `ORDER BY StageNo` দিয়ে next stage বের করবে (defensive)। |
| **B4** | Concurrency | `Purchase`-এ **`RowVersion`** (optimistic concurrency token) যোগ — double-approval race আটকাতে। |
| **B5** | Approval log rows | `PurchaseApproval` row তৈরি হবে **action-এর সময়** (approve/reject), আগে থেকে নয়। "কে pending" তা workflow stage + `CurrentStageNo` থেকে derive হয়। |

## ⚙️ অন্যান্য locked rules

| Topic | Decision |
|---|---|
| **Policy resolution — no match** | PR-এর (currency + amount) কোনো policy-তে না মিললে → **submit block** + পরিষ্কার error। |
| **Workflow lifecycle** | HMS rule মেনে আলাদা enum `EnumWorkflowStatus (Draft/Published/Archived)`; `IsActive/IsDeleted` pure soft-delete-ই থাকবে। |
| **Enum coexistence** | নতুন `ApprovalStatus` approval চালাবে; existing `EnumPurchaseRequisitionStatus (Final/Completed)` document lifecycle-এর জন্য আলাদা থাকবে (breaking change নেই)। |

---

## ⚠️ B1 vs B3 — যে অসঙ্গতি সমাধান হয়েছে

আগে B1 (whole-workflow clone) আর B3 (single-stage edit → new row) — দুটোই ছিল, যা **দুই level-এর versioning**, একসাথে গোলমাল করত।

**সিদ্ধান্ত:** শুধু **B1** রাখা হলো, **B3 বাদ**। কারণ immutable workflow-এ কখনো single stage আলাদা edit হবে না — যেকোনো পরিবর্তন = পুরো workflow clone। ফলে `StageNo` সবসময় পরপর থাকে, গ্যাপ তৈরির সুযোগই নেই।
