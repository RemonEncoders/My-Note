## 2. Role = ASP.NET Identity (`ApplicationRole`)

- Role হলো Identity-এর `ApplicationRole` (**Guid** key)।
- User ↔ Role সম্পর্ক **many-to-many**, mapping table `ApplicationUserRole` দিয়ে।
- অর্থাৎ একজন user-এর **একাধিক role** থাকতে পারে, আর একটা role-এ **অনেক user** থাকতে পারে।

> ❗ **প্রথম draft ERD-এর `User.RoleId` (এক user = এক role) ধারণাটি ভুল ছিল।** বাস্তব design এই many-to-many মেনেই হবে।

## 3. Base classes

```
Entity
 ├─ Id (Guid)
 ├─ IsActive
 └─ IsDeleted

AuditableEntity : Entity
 ├─ CreatedBy
 ├─ Created
 ├─ LastModifiedBy
 └─ LastModified
```

- সব নতুন entity `AuditableEntity` থেকে inherit করবে → উপরের field-গুলো **free** (আবার declare করা লাগবে না)।
- Base-এ **কোনো `RowVersion` নেই** → concurrency-র জন্য আলাদা যোগ করতে হবে (দেখুন B4)।

---

## 4. ⭐ HMS Architecture Rule (must respect)

`IsActive` এবং `IsDeleted` **শুধুই soft-delete flag**:

- `IsActive = true` → "not deleted"
- `IsDeleted = true` → "deleted"

> এগুলোকে **workflow lifecycle** (Draft / Published / Archived) বোঝাতে overload করা **যাবে না**। Lifecycle-এর জন্য **আলাদা enum column** লাগবে (`EnumWorkflowStatus`)।

## 5. বিদ্যমান enum

```
EnumPurchaseRequisitionStatus : Inactive=0, Draft=1, Final=2, Completed=3
```

> এতে **কোনো approval state নেই**। তাই approval-এর জন্য আলাদা enum বানানো হবে (দেখুন [05. Enums](<05. Enums.md>)), যাতে existing code না ভাঙে।
