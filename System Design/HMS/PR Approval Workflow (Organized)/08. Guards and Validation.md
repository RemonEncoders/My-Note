# 08 · Guards & Validation

> Engine-এর প্রতিটি critical point-এ যে যে rule enforce করতে হবে।

---

## Approve / Reject action

- Acting user-এর কাছে `CurrentStage.RoleId` থাকতে হবে (A1)।
- PR অবশ্যই `PendingApproval` অবস্থায়।
- **`RowVersion` concurrency check** pass করতে হবে (B4) — একই stage-এ দুই user একসাথে approve চাপলে double-advance আটকাতে।

---

## Submit

- Target workflow অবশ্যই **`Published`** এবং তাতে ≥1 active stage আছে।
- **প্রতিটি stage-এর role-এ ≥1 active user আছে** — এটা **A1 deadlock guard**। (কোনো stage-এর role-এ user না থাকলে PR চিরতরে আটকে যাবে।)
- Policy match হতে হবে (দেখুন [06](<06. Policy Resolution Logic.md>)); না মিললে submit block।

---

## Amount edit

- `ApprovalStatus == PendingApproval` হলে amount edit **blocked** (A4)।
- Draft অবস্থায় free।

---

## Policy save

- একই currency-তে **overlapping range** থাকলে reject — যাতে resolution-এ >1 match না হয়।

---

## Self-approval (A2)

- Creator-কে **সজ্ঞানে** নিজের PR approve করার অনুমতি দেওয়া হয়েছে। কোনো segregation-of-duties block নেই।

---

## সারসংক্ষেপ (checklist)

| Guard | কোথায় | কেন |
|---|---|---|
| Role match | Approve/Reject | A1 |
| Status = PendingApproval | Approve/Reject | valid transition |
| RowVersion | Approve/Reject | B4 double-approval |
| Workflow Published + stages | Submit | valid config |
| প্রতি role-এ ≥1 user | Submit | A1 deadlock |
| Policy match | Submit | routing |
| Amount edit lock | Edit | A4 |
| No overlapping range | Policy save | resolution safety |
