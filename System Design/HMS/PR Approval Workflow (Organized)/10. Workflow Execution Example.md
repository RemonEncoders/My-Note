# 10 · Workflow Execution Example (ধাপে ধাপে)

> একটা বাস্তব PR কীভাবে শুরু থেকে শেষ পর্যন্ত approval-এর মধ্য দিয়ে যায়।

---

## Sample data

**ApprovalPolicy:**

| PolicyId | MinAmount | MaxAmount | Workflow |
|---|---|---|---|
| 1 | 0 | 99,999 | Workflow 1 |
| 2 | 1,00,000 | 9,99,999 | Workflow 2 |
| 3 | 10,00,000 | NULL | Workflow 3 |

**Workflow 3 stages:**

| StageNo | Role | IsMandatory |
|---|---|---|
| 1 | Manager | Yes |
| 2 | GM | Yes |
| 3 | CEO | Yes |

---

## দৃশ্যপট: PR Amount = 12,50,000

### Step 1 — Policy match

```
12,50,000  →  10,00,000 to NULL  →  Workflow 3
```

### Step 2 — Workflow stages পড়া

```
Stage 1 → Manager
Stage 2 → GM
Stage 3 → CEO
```

PR-এ snapshot: `WorkflowId = 3`, `CurrentStageNo = 1`, `ApprovalStatus = PendingApproval`।

### Step 3 — প্রাথমিক অবস্থা

| Stage | Role | Status |
|---|---|---|
| 1 | Manager | **Pending** |
| 2 | GM | Waiting |
| 3 | CEO | Waiting |

*(Waiting rows আসলে DB-তে তৈরি হয় না — B5; শুধু বোঝানোর জন্য দেখানো।)*

### Step 4 — Manager approve

```
Manager   Approved      → PurchaseApproval row insert
GM        Pending        → CurrentStageNo = 2
CEO       Waiting
```

### Step 5 — GM approve

```
Manager   Approved
GM        Approved       → CurrentStageNo = 3
CEO       Pending
```

### Step 6 — CEO approve

```
Manager   Approved
GM        Approved
CEO       Approved
      ↓
CurrentStageNo = null
ApprovalStatus = Approved   ✅
```

---

## Dynamic-এর প্রমাণ: নতুন stage যোগ

Business যদি বলে "CEO-র আগে CFO লাগবে" —

**Immutable rule অনুযায়ী** পুরনো Workflow 3 clone করে নতুন workflow বানানো হবে:

| StageNo | Role |
|---|---|
| 1 | Manager |
| 2 | GM |
| 3 | CFO |
| 4 | CEO |

> **Database design পরিবর্তন করতে হবে না** — শুধু নতুন workflow + stage row। পুরনো Workflow 3 → Archived, চলমান PR-রা অক্ষত।
