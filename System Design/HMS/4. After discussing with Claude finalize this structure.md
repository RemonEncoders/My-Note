# SCM — Purchase Requisition (PR) Multi-Stage Approval

### Design Specification (Source of Truth)

**Module:** SCM · **Project:** HMS · **Status:** Design LOCKED, awaiting "code" green-light

---

## 1. Business Requirement

PR needs **amount-based, sequential, multi-stage approval**. The rules must be **configurable/data-driven** (not hard-coded), because approval stages and thresholds will change in the future.

Original example rules:

|PR Amount|Approver|
|---|---|
|Below 1 Lakh (< 1,00,000)|One approver|
|1 Lakh – 10 Lakh|Manager|
|Above 10 Lakh (> 10,00,000)|CEO|

These are **examples of data**, not code branches. New thresholds/approvers must be addable without code changes.

---

## 2. Existing System Context (facts discovered in the codebase)

These ground the design and must not be broken:

- **PR entity** = `Purchase` (`HMS.Entities/Areas/SCM/Purchase.cs`).
    - PR No = `PurchaseRequisitionNumber`; amount = `TotalPrice` (a **cached header total**, recomputed from `PurchaseRequisitionItems` on every save — items are source of truth).
    - Has `CurrencyId` (multi-currency capable), `RequestedById`, existing `Status` of type `EnumPurchaseRequisitionStatus`.
- **Roles** = ASP.NET Identity `ApplicationRole` (Guid). User↔Role is **many-to-many** via `ApplicationUserRole` — a user can hold multiple roles, and a role has many users. (The original ERD's `User.RoleId` single-role assumption is **not** how the system works.)
- **Base classes:**
    - `Entity` → provides `Id (Guid)`, `IsActive`, `IsDeleted`.
    - `AuditableEntity : Entity` → adds `CreatedBy`, `Created`, `LastModifiedBy`, `LastModified`.
    - No `RowVersion` in base.
- **HMS architecture rule (must respect):** `IsActive` and `IsDeleted` are **only** soft-delete flags — `IsActive = true` means "not deleted", `IsDeleted = true` means "deleted". They must **not** be overloaded to represent workflow lifecycle (Draft/Published/Archived). Lifecycle needs a **separate enum column**.
- Existing enum `EnumPurchaseRequisitionStatus` = `Inactive=0, Draft=1, Final=2, Completed=3` (no approval states).

---

## 3. Locked Decisions

|#|Topic|Decision|
|---|---|---|
|**A1**|Who approves a stage|**Role-based** — any one active user holding the stage's role can approve.|
|**A2**|Self-approval|**Allowed** — if the creator holds the stage's role, they may approve their own PR. No segregation-of-duties block.|
|**A3**|Currency handling|**Currency is configured on `ApprovalPolicy` (required field).** No currency conversion. Policy matching is by currency **and** amount range.|
|**A4**|Amount edit after submit|**Free-edit while Draft.** Once approval starts (`PendingApproval`), amount edits are **blocked**.|
|**A5**|PR approval states|**Separate enum** `EnumPRApprovalStatus`: `Draft → PendingApproval → Approved → Rejected → Cancelled`. Existing `Status` stays untouched (no breaking change).|
|**A6**|Rejection behavior|Reject = full **Rejected**. Creator may edit & **resubmit → brand-new cycle starting from stage 1**.|
|**B1**|Workflow versioning|**Workflow is immutable once Published.** Any change = **clone** the whole workflow (old → Archived, new → Published). `WorkflowId` itself acts as the version. No stage-level editing.|
|**B2**|`IsMandatory` on stage|Keep the flag for the future; **for now all stages are mandatory** (no skip/optional logic implemented).|
|**B3**|Stage-level versioning|**Dropped** — superseded by B1. Within a workflow, `StageNo` is always contiguous. Engine still finds next stage via `ORDER BY StageNo` (defensive).|
|**B4**|Concurrency|Add **`RowVersion`** (optimistic concurrency token) on `Purchase` to prevent double-approval races.|
|**B5**|Approval log rows|`PurchaseApproval` rows are created **on action** (approve/reject), not pre-created. "Who is pending" is derived from workflow stages + `CurrentStageNo`.|
|**Policy resolution**|No match|If a PR's (currency + amount) matches **no policy**, **block submit** with a clear error.|
|**Workflow lifecycle**|HMS rule|Lifecycle uses a **separate enum** `EnumWorkflowStatus (Draft/Published/Archived)`; `IsActive/IsDeleted` remain pure soft-delete.|

## 6. Policy Resolution Logic (at Submit)

```
match = ApprovalPolicy WHERE
        CurrencyId == PR.CurrencyId
    AND PR.TotalPrice >= MinAmount
    AND (MaxAmount IS NULL OR PR.TotalPrice <= MaxAmount)
    AND IsActive AND NOT IsDeleted
```

- **0 matches →** block submit, error: _"No approval policy configured for this currency/amount."_
- **>1 matches →** configuration error. **Prevent at source:** validate for overlapping ranges (same currency) when a policy is saved.
- On success → take `match.WorkflowId`, snapshot it onto the PR.

---

## 7. State Flow (Sequential Engine)

```
Create ──► ApprovalStatus = Draft            (amount free-edit)

Submit ──► resolve policy → snapshot PR.WorkflowId
                          → CurrentStageNo = MIN(StageNo of that workflow)
                          → ApprovalStatus = PendingApproval   (amount edit now BLOCKED)

At CurrentStage:
  Approve  (acting user must hold stage.RoleId):
      → insert PurchaseApproval(Action=Approved)
      → next = first StageNo > CurrentStageNo   (ORDER BY StageNo)
      → if next exists:  CurrentStageNo = next
        else:            ApprovalStatus = Approved, CurrentStageNo = null

  Reject:
      → insert PurchaseApproval(Action=Rejected)
      → ApprovalStatus = Rejected, CurrentStageNo = null   (flow stops)

Rejected ──► creator edits + Resubmit ──► NEW cycle from MIN(StageNo)
                                          (previous PurchaseApproval rows retained as history)

Cancel (creator) ──► ApprovalStatus = Cancelled
```

---

## 8. Guards & Validation

- **Approve/Reject:** acting user holds `CurrentStage.RoleId`; PR is `PendingApproval`; `RowVersion` concurrency check passes.
- **Submit:** target workflow is `Published` and has ≥1 active stage; **every stage's role has ≥1 active user** (A1 deadlock guard).
- **Amount edit:** blocked when `ApprovalStatus == PendingApproval` (A4).
- **Policy save:** reject overlapping ranges within the same currency.
- **A2:** creator is explicitly permitted to approve their own PR.
