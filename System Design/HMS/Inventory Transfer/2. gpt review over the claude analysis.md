# আমার মতে এখন সবচেয়ে বড় Question

এখন আর Question না

> "Pending Receipt লাগবে কি?"

কারণ উত্তর পেয়ে গেছি।

**লাগে না। Already আছে।**

এখন Question হলো:

> **InventoryReceipt Confirm-এর সময় Destination Handler (`PharmacyReceiptDestinationHandler`) কি Hard-coded `qty` ব্যবহার করছে, নাকি আমরা ওখানেই Conversion, Unit Cost Normalization এবং Pharmacy Stock Update ঢুকাব?**

**আমার মতে এটিই এখন পুরো Refactoring-এর Heart।**

যদি Conversion Logic, Normalized Quantity, Unit Cost per Dispensing Unit এবং Override Handling—সব `InventoryReceiptService.ConfirmAsync` বা `PharmacyReceiptDestinationHandler`-এ করা যায়, তাহলে তোমার পুরো নতুন UOM Architecture খুব কম Code পরিবর্তনেই Implement করা সম্ভব হবে। আর এটাও বর্তমান Design-এর সাথে সবচেয়ে সামঞ্জস্যপূর্ণ হবে।
