# ① Projection vs Synchronization

এটা এখন একদম ঠিক।

Claude একটা গুরুত্বপূর্ণ clarification দিয়েছে।

> এটা Synchronization না, এটা Projection।

এই terminology enterprise architecture-এ খুব গুরুত্বপূর্ণ।

### কেন?

Synchronization হলে

```text
Drug

↓

Product
```

এবং

```text
Product

↓

Drug
```

দুই দিকেই update হতে পারে।

তখন conflict resolution লাগবে।

কিন্তু Projection হলে

```text
Drug
      │
      ▼
Product
```

শুধু একটাই direction।

Product হচ্ছে

> Read Model

অথবা

> Materialized Projection

এটা আমি ১০০% সমর্থন করি।

# Final Verdict

এখন Design-এর maturity আমার কাছে প্রায় **9.8/10**।

শুধু **একটাই open design choice** বাকি আছে:

### Option A (Claude)

```
Publish

↓

Drug.ProductId = value

↓

Discontinue

↓

Drug.ProductId = null

↓

Republish

↓

Link Table থেকে Product খুঁজে আবার ProductId set
```

**সুবিধা:**

- বর্তমান publish state বোঝা সহজ (`ProductId == null` মানে published নয়)।
    
- Derivation logic সরল।
    

---

### Option B (আমার পছন্দ)

```
Publish

↓

Drug.ProductId = value

↓

Discontinue

↓

Product.IsActive = false

↓

Drug.ProductId অপরিবর্তিত

↓

Republish

↓

Product.IsActive = true
```

**সুবিধা:**

- Identity স্থায়ী থাকে।
    
- কোনো re-linking বা lookup দরকার হয় না।
    
- DDD-এর "identity is stable" নীতির সাথে বেশি সামঞ্জস্যপূর্ণ।
    

---

**এই দুইটার যেকোনো একটা বেছে নিলেই, আমার মতে architecture implementation-ready।**
