  
সঠিক ধরেছেন — CI test শুধু ধরিয়ে দেয়, প্রতিরোধ করে না। এবার প্রকৃত single-source-of-truth সমাধান দিচ্ছি, hand-waving ছাড়া।

## সরাসরি উত্তর: C# authoritative, SQL View তার একটা _generated artifact_ — independently-authored দ্বিতীয় সত্য নয়

দুটো implementation লেখার বদলে, rule-টা **একবারই** লেখা হবে — একটা `Expression<Func<Product, bool>>` হিসেবে (plain method না), যেটা C#-এ compile করেও চালানো যায়, আবার EF Core দিয়ে SQL-এও translate করা যায়:

```csharp
public static class ProductProcurementReadinessPolicy
{
    // এটাই একমাত্র জায়গা যেখানে rule লেখা হয় — বাকি সব এখান থেকেই derive/generate হবে।
    public static readonly Expression<Func<Product, bool>> IsSourceable =
        p => p.CategoryId != null && p.MeasurementUnitId != null;

    public static readonly Expression<Func<Product, bool>> IsPurchasable =
        p => p.CategoryId != null && p.MeasurementUnitId != null && p.ValuationClassId != null;
        // future: && p.TaxProfileId != null && p.CostCenterId != null ...
}
```

**অ্যাপ্লিকেশন-সাইড ব্যবহার** (PO Confirm guard, PR/RFQ badge) — একই expression, compile করে in-memory evaluate, অথবা সরাসরি EF LINQ query-তে বসিয়ে:

```csharp
bool ready = ProductProcurementReadinessPolicy.IsPurchasable.Compile().Invoke(product);
// অথবা: _context.Products.Where(ProductProcurementReadinessPolicy.IsPurchasable)
```

**SQL View — hand-written না, generated।** এই কোডবেস EF Core 8.0.13 ব্যবহার করে ([HMS.Repository.csproj:9](vscode-webview://0tri44ar51et483btke71i178mqksugck1rce8n1q6b1u371eioe/HMS.Repository/HMS.Repository.csproj#L9)), যেখানে `IQueryable.ToQueryString()` (EF Core 5+ থেকে উপলব্ধ) দিয়ে **ঠিক একই C# expression থেকে প্রকৃত SQL টেক্সট বের করা যায়**:

```csharp
var sql = _context.Products
    .Where(ProductProcurementReadinessPolicy.IsPurchasable)
    .Select(p => p.Id)
    .ToQueryString();   // ← EF নিজেই SQL জেনারেট করে দেয়, আমরা হাতে লিখি না
```

মাইগ্রেশন-লেখার সময় এই generated SQL-টাই `CREATE VIEW`-এ বসানো হয় — অর্থাৎ **DBA যা query করবেন, সেটা মানুষের হাতে লেখা দ্বিতীয় copy না, C# rule থেকে mechanically derived একটা build artifact।** ঠিক যেভাবে EF migration নিজেই schema DDL C# entity থেকে generate করে (হাতে লেখা DDL না) — এখানে একই নীতি একটা business-rule view-তে প্রসারিত করা হচ্ছে, নতুন কোনো foreign টেকনিক না।

## Workflow যখন নতুন accounting field আসবে (যেমন `TaxProfileId`)

1. `IsPurchasable` expression-এ এক লাইন যোগ: `&& p.TaxProfileId != null`।
2. `ToQueryString()` আবার চালানো — fresh SQL বেরিয়ে আসে।
3. সেই SQL নতুন migration-এর `CREATE OR ALTER VIEW`-এ বসানো।
4. একটাই commit — rule আর view একসাথে বদলায়, কারণ view-এর টেক্সটটাই rule থেকে এসেছে, আলাদাভাবে "মনে রেখে" আপডেট করা হয়নি।

## CI test-কে "detect" থেকে "prevent"-এ upgrade

আগের turn-এ যে contract test প্রস্তাব করেছিলাম, সেটা এখন আরও কঠোর করা যায় — behavior compare না, **exact generated-text compare**:

```csharp
[Test]
void MigrationViewSqlMustMatchCurrentPolicy()
{
    var freshlyGenerated = _context.Products
        .Where(ProductProcurementReadinessPolicy.IsPurchasable)
        .ToQueryString();

    var sqlStoredInLatestMigration = ReadEmbeddedViewSql("vw_ProductProcurementReadiness");

    Assert.Equal(NormalizeWhitespace(freshlyGenerated), NormalizeWhitespace(sqlStoredInLatestMigration));
}
```

এটা আর "দুটো independent implementation কি একই আচরণ করছে" পরীক্ষা না — এটা "migration-এ যা আছে সেটা কি আজকের C# rule থেকে literally derive করলে যা পেতাম তাই" পরীক্ষা। কেউ `IsPurchasable`-এ পরিবর্তন করে migration আপডেট করতে ভুলে গেলে, এই test build-এই fail করবে, merge হওয়ার আগেই — অর্থাৎ এখন এটা সত্যিই **prevent** করছে, শুধু পরে ধরিয়ে দিচ্ছে না।

## সততার সাথে একটা সীমাবদ্ধতা

এই পদ্ধতি কাজ করে কারণ আমাদের rule সহজ — শুধু null-check আর boolean AND, যেটা EF Core নির্ভুলভাবে SQL-এ translate করতে পারে। ভবিষ্যতে যদি কোনো accounting rule pure-CLR-only logic দাবি করে (যেমন কোনো external service call বা জটিল non-SQL-translatable calculation) — যেটা এই ধরনের null-check invariant-এর জন্য বাস্তবসম্মত না — তখন এই generation-approach ভেঙে পড়বে এবং সেই মুহূর্তে সচেতনভাবে পুনর্বিবেচনা লাগবে। এখনকার জন্য এটা কোনো বাধা না, কিন্তু লুকিয়ে রাখছি না।
