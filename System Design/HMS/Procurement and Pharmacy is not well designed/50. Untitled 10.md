হ্যাঁ, পুরো conversation-এর decision trail আমার কাছে আছে। যাচাইয়ের জন্য git status ও চেক করেছি — এখনো কিছুই commit হয়নি, সব change working tree-তে আছে। নিচে সম্পূর্ণ সারসংক্ষেপ, আপনার চাওয়া বিভাগ অনুযায়ী।

## ১. মূল সমস্যা (যা থেকে শুরু)

SCM manual Product Add আর PHAR Drug Publish — দুটো path একই `Product` টেবিলে ভিন্ন completeness-level-এর record তৈরি করছিল। প্রশ্ন ছিল: এটা কি enterprise invariant ভঙ্গ করছে, আর যদি করে, সঠিক domain-driven সমাধান কী।

## ২. Audit থেকে পাওয়া প্রমাণ (business rule)

- `Product` entity-তে কোনো DB-level `[Required]` নেই — SCM Add screen-এর "required" মার্কিং আসলে UI-workflow সিদ্ধান্ত, domain invariant না (ব্যতিক্রম নিচে)।
- **প্রকৃত invariant প্রমাণিত হয়েছে দুটো**:
    - **`ValuationClassId`** — null হলে `MaterialGLFindService`-এ `Guid.Empty` তৈরি হয়ে GoodsReceive/InvoiceReceive/StockOut — তিন জায়গাতেই silently ভুল GL account-এ journal entry পোস্ট হয়।
    - **`ItemType`** — ঐতিহাসিকভাবে ভুল থাকলে Product PR/PO/GR picker থেকে অদৃশ্য হয়ে যেত (আপনার working tree-তেই থাকা uncommitted migration `BackfillPublishedDrugItemType` এটা backfill করছে) — এটা ইতিমধ্যে fix হয়ে গেছে, `ProductPublisher.cs`-এ সঠিকভাবে hardcoded।
- `CategoryId`/`MeasurementUnitId` — null হলে crash করে (কিছু নির্দিষ্ট report/endpoint-এ), কিন্তু `ProductPublisher` এগুলো এমনিতেই পূরণ করে, তাই gap নেই।
- `UnitPrice`, `PurchasePrice`, `Vat`, `PurchaseVat` — soft/orphaned fields, UI-তে "required" দেখালেও কোড নিজেই `?? 0` করে — প্রকৃত invariant না।

## ৩. DDD Ownership সিদ্ধান্ত

- **`ValuationClass` = Finance/SCM-এর domain knowledge, Pharmacy-র না** — এটা multi-company নিয়ে না, authority নিয়ে যুক্তি (single-company হলেও Pharmacist Chart-of-Accounts owner না)।
- **`Drug`, `ProductPublisher`, `ProductPublishRequest` — কখনো পরিবর্তন হবে না, একদম প্রথম সিদ্ধান্ত থেকে শেষ implementation পর্যন্ত অক্ষত।**

## ৪. Procurement Lifecycle — enforcement point বিশ্লেষণ

বিবেচিত ও **বাতিল**: Drug creation (ভুল bounded context), Product publication (Finance-এর SLA-তে Pharmacy আটকানো ভুল), PR/RFQ creation (demand-sensing over-gate করা, vendor lead-time-কে ভুল কারণে block করা), GRN/accounting posting (fail-late, দেরিতে ব্যয়বহুল)।

**চূড়ান্ত সিদ্ধান্ত: PO Confirm (Draft→Final transition)** — এই কোডবেসের নিজস্ব precedent-এর সাথে মিলিয়ে (quantity-reservation-ও Draft-এ না, Confirm-এ কমিট হয়, [EnumPurchaseOrderStatus.cs:31-33](vscode-webview://0tri44ar51et483btke71i178mqksugck1rce8n1q6b1u371eioe/HMS.Common/Enums/EnumPurchaseOrderStatus.cs#L31-L33))।

## ৫. যে over-engineering বাতিল হয়েছে (গুরুত্বপূর্ণ self-correction)

আলোচনার মাঝপথে যেসব প্রস্তাব দিয়ে পরে **প্রত্যাখ্যান** করা হয়েছে, ভবিষ্যতে যেন আবার প্রস্তাব না হয়:

- ❌ "Procurement Readiness" নামে তিন-স্তরের named domain state (Published/Sourceable/Purchasable) — codebase-এ এই terminology-র কোনো অস্তিত্ব নেই, এটা SAP থেকে ধার করা আমদানি ছিল, business ভাষা না।
- ❌ Materialized `ProcurementReadinessStatus` column — "derived state, never stored" নীতির সাথে সাংঘর্ষিক।
- ❌ SQL View + EF `ToQueryString()` generation, Expression-tree ভিত্তিক Specification pattern — এমন একটা DBA/reporting প্রয়োজন সমাধান করছিল যেটা কখনো চাওয়া হয়নি, আর business rule দুই জায়গায় duplicate করছিল।

## ৬. চূড়ান্ত, বাস্তবায়িত architecture

একটা flat, independent validation-list, একটাই enforcement point-এ:

```
ValidationError { Code, Message, ProductId }
IProductPurchaseEligibilityValidator.Validate(Product) -> List<ValidationError>
    → আপাতত শুধু: ValuationClassId == null চেক
    → ভবিষ্যতে TaxProfile/CostCenter/InventoryAccount/WarehouseProfile/LotPolicy/ColdChain — প্রতিটা একটা করে independent স্বতন্ত্র if-block

PurchaseOrderService.UpdateStatusAsync() [status == Final]
    → GuardPurchaseRequisitionReservationAsync()  (বিদ্যমান)
    → GuardRfqItemReservationAsync()              (বিদ্যমান)
    → GuardProductPurchaseEligibilityAsync()       (নতুন) — PO-র প্রতিটা distinct Product validate,
                                                       সব error একসাথে BusinessRuleException-এ
```

## ৭. Database Design

**কোনো নতুন migration লাগেনি** — `Product.ValuationClassId` আগে থেকেই বিদ্যমান column (এই কাজে কোনো schema change নেই)। `Drug` টেবিলেও কোনো column যোগ হয়নি (আগের প্রস্তাব বাতিল হয়েছিল বলে)।
