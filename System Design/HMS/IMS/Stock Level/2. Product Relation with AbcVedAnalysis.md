## দৃশ্যপট: ১ জুলাই, স্টোর ম্যানেজার "Recalculate" চাপলেন

সিস্টেম গত ১২ মাসের consumption ঘেঁটে প্রতিটা product-এর মোট খরচের টাকা বের করল:

|Product|১২ মাসে খরচ (৳)|Ranking করে class|
|---|---|---|
|Insulin|৪০,০০,০০০|A|
|Suture|৮,০০,০০০|B|
|Gauze|২,০০,০০০|C|
|Syringe|১,৫০,০০০|C|
|Vitamin|৫০,০০০|C|

এখন `scm_products` টেবিলে প্রতিটা row-তে ৩টা জিনিস লেখা হলো:

```
Insulin:  AbcClass = A,  AbcAnnualValue = 40,00,000,  AbcCalculatedOn = 01-Jul
Suture:   AbcClass = B,  AbcAnnualValue = 8,00,000,   AbcCalculatedOn = 01-Jul
...
```

এই মুহূর্তে হিসাবটা **শেষ**। এরপর যে-ই পেজ খুলুক, আর কোনো হিসাব হয় না — শুধু এই ৩টা কলাম পড়া হয়।

## `AbcAnnualValue` কেন লাগে — সমস্যাটা ১৫ আগস্টে দেখা যায়

ধরুন আমরা value **stamp করিনি**, শুধু class stamp করেছি। এখন ১৫ আগস্ট আপনি Analysis পেজ খুললেন। পেজে দেখাতে হবে: _"A class: 1 item, ৳ কত?"_

টাকার অঙ্কটা কোথা থেকে আসবে? দুটো পথ, দুটোই খারাপ:

**পথ ১ — প্রতিবার আবার হিসাব:** পেজ খোলামাত্র সিস্টেম আবার ১২ মাসের লাখ লাখ transaction স্ক্যান করবে। যে ভারী কাজটা এড়াতে class stamp করলাম, সেটাই প্রতি page load-এ ফিরে এলো। লাভ শূন্য।

**পথ ২ — হিসাব করলাম, কিন্তু সংখ্যা মিলল না:** ধরুন জুলাই-আগস্টে Insulin-এর ব্যবহার হঠাৎ কমে গেছে। ১৫ আগস্টে নতুন করে হিসাব করলে Insulin-এর value আসে ৳১২,০০,০০০ — যা Suture-এর চেয়েও কম। কিন্তু class তো ১ জুলাইয়ের stamp করা `A`-ই রয়ে গেছে! পেজে দেখাবে:

> Insulin — **Class A** — ৳১২,০০,০০০ Suture — **Class B** — ৳১৪,০০,০০০ ← B-এর টাকা A-এর চেয়ে বেশি?!

ব্যবহারকারী ভাববে সিস্টেম ভাঙা। আসলে class আর value **দুই ভিন্ন সময়ের** হিসাব — এই অসঙ্গতিটাই bug।

**সমাধান:** যে মুহূর্তে class ঠিক হলো, ঠিক যে সংখ্যার ভিত্তিতে হলো — সেই সংখ্যাটাই পাশের কলামে (`AbcAnnualValue`) লিখে রাখো। তাহলে পেজ সবসময় দেখাবে: _"Insulin A হয়েছে, কারণ তখন তার value ছিল ৳৪০,০০,০০০"_ — রায় আর প্রমাণ একসাথে, একই তারিখের। আদালতের রায়ের সাথে যেমন সাক্ষ্যপ্রমাণ নথিভুক্ত থাকে — পরে সাক্ষী মত বদলালেও নথি বদলায় না।

## `AbcCalculatedOn` কেন লাগে — সমস্যাটা ডিসেম্বরে দেখা যায়

এবার ধরুন timestamp কলামটা **নেই**। ডিসেম্বরে নতুন একজন procurement officer পেজ খুলে দেখলেন Insulin = A। তিনি এর ভিত্তিতে dual-supplier চুক্তি আর monthly cycle count-এর বাজেট বানালেন।

তিনি যেটা জানেন না: শেষ Recalculate হয়েছিল **৫ মাস আগে, ১ জুলাইয়ে**। এর মধ্যে হাসপাতালে নতুন oncology ইউনিট খুলেছে, দামি ওষুধের consumption সম্পূর্ণ বদলে গেছে — কিন্তু কেউ Recalculate চাপেনি। উনি ৫ মাসের বাসি classification-এর উপর টাকা ঢালছেন, এবং **এটা জানার কোনো উপায়ই পেজে নেই।**

`AbcCalculatedOn` থাকলে পেজের কোণায় লেখা থাকে:

> 🕐 ABC as of: **01-Jul-2026**

ডিসেম্বরে এটা দেখামাত্র উনি বুঝবেন — "৫ মাস পুরনো, আগে Recalculate চাপি।" একটা কলাম = ভুল সিদ্ধান্ত থেকে রক্ষা।

দ্বিতীয় ব্যবহার: জবাবদিহি। কেউ যদি প্রশ্ন করে _"Suture-কে B বানাল কে, কবে?"_ — উত্তর টেবিলেই আছে। আর কোনো item-এর `AbcCalculatedOn` যদি `null` হয়, তার মানে সেটা জন্মের পর কখনো classification-এর ভেতর দিয়েই যায়নি — সেটাও একটা তথ্য।

## এক ছবিতে তিনটা কলাম

```
RunAbcAnalysisAsync()  ──লেখে──►  AbcClass         = রায়টা কী        (A/B/C)
        (১ জুলাই)                 AbcAnnualValue   = কীসের ভিত্তিতে   (৳৪০,০০,০০০)
                                  AbcCalculatedOn  = কবে দেওয়া হলো   (01-Jul)
```

- `AbcClass` একা থাকলে জানা যায় **কী**, কিন্তু **কেন** আর **কবে** না।
- `AbcAnnualValue` "কেন"-র উত্তর — নাহলে হয় প্রতিবার ভারী পুনঃহিসাব, নয় অসঙ্গত সংখ্যা।
- `AbcCalculatedOn` "কবে"-র উত্তর — নাহলে বাসি ডেটা আর টাটকা ডেটা দেখতে একই রকম।

তিনটা একসাথে একটাই বাক্য বলে: **"এই product-টা A, কারণ ১ জুলাইয়ের হিসাবে তার বার্ষিক খরচ ছিল ৳৪০ লাখ।"** — কোনো একটা কলাম বাদ দিলে বাক্যটার একটা অংশ হারিয়ে যায়।
