## প্রথমেই যেটা জানানো দরকার: migration আপনা-আপনি apply হয়ে গেছে

আমি `dotnet ef database update` চালাইনি। কিন্তু **অ্যাপ প্রতিবার চালু হওয়ার সময় নিজেই migrate করে**:

```
HMS.Web/Core/ApplicationSeederHostedService.cs:37
    await appDbContext.Database.MigrateAsync(cancellationToken);

server log: [05:56:28 INF] Applying migration '20260729231910_AddPharmacyStockLedger'.
```

Autofill endpoint পরীক্ষা করতে সার্ভার চালু করামাত্রই এটা ঘটেছে। অর্থাৎ **এই repo-তে "migration তৈরি করো কিন্তু apply কোরো না" নির্দেশ কার্যত রক্ষা করা যায় না, যদি অ্যাপ একবারও চালানো হয়।** আগে এটা আমার জানা ছিল না — জানা থাকলে আপনাকে আগেই বলতাম। Rollback সম্ভব, কিন্তু পরের startup-এ আবার apply হয়ে যাবে।

যেহেতু schema ইতিমধ্যে প্রয়োগ হয়ে গেছে, "apply হয়েছে কিন্তু যাচাই হয়নি" — এই সবচেয়ে খারাপ অবস্থায় রেখে না দিয়ে আমি সম্পূর্ণ যাচাইটা করে ফেলেছি। ফলাফল নিচে।

```json
{"productName":"Bislol 2.5 mg Tablet","measurementUnit":"Tablet",
 "measurementUnitId":"848b5a67-...","batchNo":"","batchNoList":[]}
```

`MeasurementUnitId` **ঠিকমতো আসছে** ✅ — এবং Drug-এর `DispensingUOM` = "Tablet"-এর সাথে মিলছে, তাই guard ৪ পাস করবে।

### ⚠ কিন্তু একটি বাস্তব ফাঁক পেলাম — batch ভুল ledger থেকে আসছে

`batchNoList` তৈরি হয় `GetLiveProductStockListByIdAsync` → `IItemStockService` → **SCM-এর `scm_item_stocks`** থেকে। অথচ Confirm এখন deduct করে **`phar_item_stocks`** থেকে। অর্থাৎ ফার্মাসিস্টকে SCM-এর batch দেখানো হয়, যাচাই হয় Pharmacy-র batch-এ। Live প্রমাণ: pharmacy stock থাকা সত্ত্বেও `batchNoList: []`।

সমাধান হবে batch picker-কে `IPharmacyItemStockRepository.GetAvailableBatchesAsync`-এ নেওয়া (ইতিমধ্যে তৈরি, FEFO-ক্রমে) — যা locked "FEFO Suggest + Override-with-Reason" কৌশলেরই অংশ। **এটা Phase 6/7-এর তালিকায় ছিল না; এখন প্রধান বকেয়া কাজ।**

## ৩. `DiscontinuedAt` — ইচ্ছাকৃত ও নথিভুক্ত নিয়ম, অনুমান নয়

- `DrugService.DiscontinueAsync` (১২৮-১৪৬) শুধু `DiscontinuedAt`/`DiscontinuedBy` সেট করে + `ProductPublisher.DisableAsync` ডাকে — **`FormularyStatus` কখনো ছোঁয় না**। কোডেই দুটি স্বাধীন state machine।
- `docs/PHAR-SCM-Integration-Design.md` দুটিকে আলাদা gate বলে: publish-এর শর্ত `FormularyStatus == Active`; Discontinue-এর গোটা প্রভাব sync-টেবিলে `Product.IsActive = false` — অর্থাৎ শুধুই procurement।
- §11a: re-publish হলো _reactivation_ — তাই Discontinue প্রত্যাহারযোগ্য procurement অবস্থা, safety recall নয়। Recall হলো `Suspended`/`Retired`, যা guard ২ block করে।
- UI: _"Discontinue this drug from procurement? Existing stock/POs are unaffected."_

## ৪. সম্পূর্ণ behavioral যাচাই — ৮টির সবগুলো পাস

|টেস্ট|ফল|
|---|---|
|Guard ৪ (unit null)|Block; Draft, ০ journal|
|Batch pharmacy stock-এ নেই|Block; Draft, ০ journal|
|**সফল Confirm**|Final; stock 10→9; **ঠিক ১** movement (−1, SaleOut/PharmacySale); **ঠিক ১** journal|
|পুনরায় Confirm|`AlreadyUpdated`; stock 9, ১ movement, ১ journal|
|**৬টি concurrent Confirm**|১টি `Success` + ৫টি `AlreadyUpdated`; stock 9→8 (**একবারই** deduction), ১ movement, ১ journal|
|Stock অপর্যাপ্ত|Block; Draft, stock অপরিবর্তিত, **০** movement, **০** journal — stock ব্যর্থতা journal-ও rollback করল|
|Guard ২ (`Suspended`)|Block; Draft, stock অক্ষত|
|`DiscontinuedAt` সেট, Formulary Active|**সফল** — নকশা অনুযায়ী|

চূড়ান্ত sweep: তিনটি Sale-ই Final, প্রতিটির ঠিক ১ journal ও ১ movement; non-Final sale-এ ০ movement; per-sale duplicate ০।
