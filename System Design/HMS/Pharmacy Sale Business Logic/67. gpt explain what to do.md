Claude খুব ভালো একটি সমস্যা ধরেছে। এখানে সত্যিই **naming collision** আছে।

বর্তমান entity-তে ইতিমধ্যেই আছে:

```csharp
public EnumPaymentType PaymentType { get; set; }
```

যার অর্থ:

- Invoice Payment
    
- Advance Payment
    

অন্যদিকে নতুনটি বোঝাচ্ছে:

- Cash
    
- Bank
    
- Card
    
- Mobile Banking
    

এগুলো এক জিনিস নয়।

---

## তবে আমি একটা বিষয় পরিবর্তন করব

Claude বলেছে:

> PaymentTypeId থাকবে, navigation হবে PaymentMode

আমি এটা করব না।

কারণ এতে আবার inconsistency হবে।

```csharp
PaymentTypeId
PaymentMode
```

একই relationship-এর FK এবং Navigation-এর নাম আলাদা।

এটা EF Core-এ কাজ করলেও domain model-এর জন্য সুন্দর না।

---

## আমার Recommendation

**দুটোই PaymentMode নামে rename করুন।**

অর্থাৎ:

```csharp
public Guid? PaymentModeId { get; set; }

public GeneralConfig PaymentMode { get; set; }
```

এবং পুরোনো

```csharp
public EnumPaymentType PaymentType { get; set; }
```

যেমন আছে তেমনই থাকবে।

তখন entity পড়লে একদম পরিষ্কার হবে।

```text
PaymentType
    ↓
Advance / Invoice

PaymentMode
    ↓
Cash / Card / Bank / Mobile Banking
```

দুইটা concept আলাদা, নামও আলাদা।

---

## আরও ভালো নাম?

অনেক ERP/HIS-এ এই terminology ব্যবহার হয়:

- **Payment Type** → Invoice / Advance / Refund
    
- **Payment Mode** → Cash / Card / Bank / Mobile Banking
    

এটা industry-তেও খুব common।

## আমি Claude-কে এভাবেই বলতাম

> Naming collisionটি valid।
> 
> তবে `PaymentTypeId` রেখে শুধু navigation-কে `PaymentMode` নাম দিতে চাই না। FK এবং navigation একই business concept represent করে, তাই তাদের নামও consistent হওয়া উচিত।
> 
> `PharmacyCustomerPayment`-এ নতুন GeneralConfig relationship-টি:
> 
> ```csharp
> public Guid? PaymentModeId { get; set; }
> public GeneralConfig PaymentMode { get; set; }
> ```
> 
> এভাবে rename করো।
> 
> বিদ্যমান
> 
> ```csharp
> public EnumPaymentType PaymentType { get; set; }
> ```
> 
> অপরিবর্তিত থাকবে, কারণ সেটা Advance বনাম Invoice Payment বোঝায়।
> 
> এরপর ViewModel, Service, Repository, Mapping, Validation এবং Migration—সব জায়গায় `PaymentModeId` naming consistent রাখো।

এটাই সবচেয়ে পরিষ্কার, self-documenting এবং ভবিষ্যতে বিভ্রান্তি কমাবে।
