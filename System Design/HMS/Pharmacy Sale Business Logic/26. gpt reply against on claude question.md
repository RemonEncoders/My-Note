আমি **Config-এ রাখার পক্ষে নই**, আবার **Warehouse Name দিয়ে Resolve করার পক্ষেও পুরোপুরি নই**।

Enterprise Architecture অনুযায়ী আমি তৃতীয় একটি পদ্ধতি সুপারিশ করব।

### Claude-কে এই উত্তর দিন

> **Don't hardcode the warehouse name and don't put it in configuration.**
> 
> Since the current business rule guarantees that there is only one Pharmacy Warehouse, resolve it through a dedicated domain/service method instead of embedding the lookup strategy throughout the code.
> 
> For example, expose something like `IPharmacyWarehouseService.GetDefaultWarehouseAsync()` (or an equivalent domain abstraction). Internally it can currently return the single seeded Pharmacy Warehouse. If the implementation initially looks it up by a seeded flag or name, that's acceptable, but that lookup should remain encapsulated in one place.
> 
> This way, `PharmacySaleService` and future `PharmacyItemStock` logic never depend on how the warehouse is found. If, in the future, we introduce multiple pharmacy warehouses or allow administrators to configure the default warehouse, only the implementation of that service needs to change—not the sales or stock code.
> 
> So please encapsulate the warehouse resolution behind a single abstraction and continue with Phase 2.
