## নতুন প্রয়োজন বোঝা: Split Payment

এক `PharmacyCustomerPayment`-এ একাধিক payment mode (Cash + Card + Bank ইত্যাদি), প্রতিটার নিজস্ব amount ও optional reference। এর মানে header-level single `PaymentModeId`/`Amount` যথেষ্ট না — একটা **child collection** লাগবে, ঠিক `PharmacyCustomerPaymentInvoice`/`PharmacyCustomerPaymentAdvance`-এর মতোই already-established প্যাটার্নে।

## প্রস্তাবিত ডিজাইন

### নতুন child entity: `PharmacyCustomerPaymentMode`

```
CustomerPaymentId  (Guid, FK -> PharmacyCustomerPayment)
PaymentModeId      (Guid, FK -> GeneralConfig, PaymentType master — একই source যা আগে confirm হয়েছে)
Amount             (decimal)
ReferenceNo        (string, optional — cheque/transaction ref, mode-ভিত্তিক)
```

`PharmacyCustomerPayment.PaymentModes` (`IList<PharmacyCustomerPaymentMode>`) — ঠিক `CustomerPaymentEntryInvoices`/`CustomerPaymentEntryAdvances`-এর মতোই sibling child collection।

**গুরুত্বপূর্ণ**: এটা আগে বাদ দেওয়া `PharmacyCustomerPaymentGl`-এর প্রত্যাবর্তন না। পার্থক্য স্পষ্ট — user এখানে শুধু **business-friendly PaymentMode (Cash/Card/Bank) + Amount** দেয়, কখনো `GlMasterId`/`DcType`/`Narration` সরাসরি টাচ করে না। GL এখনো ১০০% auto-computed, প্রতিটা line-এর জন্যই।

### Header-level পরিবর্তন

- Header-এর একক `PaymentModeId`/`PaymentMethodId` **সরিয়ে ফেলা হবে** — এখন সেটা child collection-এ চলে যাচ্ছে
- Header-এর `ReferenceNo` (Cheque/Ref) **এখন redundant** — যেহেতু reference per-mode হয়ে গেছে, এটা বাদ দেওয়াই যুক্তিসঙ্গত (নাকি header-এ একটা "general remarks/ref" হিসেবে রাখতে চান, সেটা আপনার সিদ্ধান্ত)
- Header-এর `Amount` — এখন এটা কি (ক) user-এর declared total (validate করা হবে sum-এর বিপরীতে), নাকি (খ) সরাসরি বাদ দিয়ে সবসময় mode-lines-এর sum থেকে computed/derived — এটা একটা open decision point

### `PaymentTypeGlMapping`/`IPaymentGlResolver` reuse — অপরিবর্তিত

কোনো পরিবর্তন লাগবে না — প্রতিটা mode-line-এর জন্য আলাদাভাবে `ResolveGlIdAsync(modeLine.PaymentModeId)` কল হবে।

### Journal Posting শেপ (PostJournalAsync-এর সংশোধিত লজিক)

```
foreach (var mode in entity.PaymentModes)
{
    Debit  = IPaymentGlResolver.ResolveGlIdAsync(mode.PaymentModeId)
    Amount = mode.Amount
}
// শেষে একটা মাত্র Credit line:
Credit = customer.ReconGlId (Invoice Payment) / AdvanceGlId (Advance Payment)
Amount = Sum(entity.PaymentModes.Select(x => x.Amount))
```

N-টা debit line + ১টা credit line — sum(debit) == credit স্বয়ংক্রিয়ভাবে balance থাকবে যদি header Amount বাদ দিয়ে sum থেকে derive করা হয় (validation সহজ হয়ে যায়)।

3. **`PharmacySale`-এর নিজস্ব `PaymentTypeId` (single, header-level, একটু আগে করা rename)-ও কি একই split-payment treatment পাবে, নাকি Sale আপাতত single-mode-ই থাকবে?** — আপনি স্পষ্টভাবে শুধু Payment-এর কথা বলেছেন, তাই ধরে নিচ্ছি Sale অপরিবর্তিত থাকবে, কিন্তু নিশ্চিত হতে চাই।
4. এন্টিটির নাম `PharmacyCustomerPaymentMode` ঠিক আছে, নাকি অন্য নাম চান?
