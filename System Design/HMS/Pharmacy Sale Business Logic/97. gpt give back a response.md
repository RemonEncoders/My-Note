### কেন এটা এত গুরুত্বপূর্ণ

ধরুন:

```
Sale S001

Batch: TESTBATCH02
Qty: 5

↓

Confirm

↓

Stock: -5
Journal: $100
Movement: -5
```

এরপর যদি Edit করে user পরিবর্তন করে:

```
Qty: 8

অথবা

Batch: TESTBATCH01
```

তাহলে কী হবে?

Database-এ থাকবে:

- Sale = Qty 8
    
- Journal = Qty 5-এর হিসাব
    
- Stock Movement = Qty 5
    
- Inventory = Qty 5 কাটা
    

অর্থাৎ Sale document আর Accounting/Inventory আর একে অপরের সাথে মিলবে না।

এটা enterprise ERP/HIS-এ খুব বড় integrity সমস্যা।

## Enterprise pattern কী?

সাধারণত Confirm/Final হওয়ার পর:

```
Draft
   ↓
Final
   ↓
Immutable
```

যদি পরিবর্তন করতে হয়, তাহলে:

```
Final Sale

↓

Reverse / Return

↓

নতুন Sale
```

সরাসরি Edit নয়।

Status == Draft

Edit Allowed
