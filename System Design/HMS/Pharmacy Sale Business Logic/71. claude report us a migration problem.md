মাইগ্রেশন ফাইল (`AddPharmacySaleAndCustomerPaymentTables`) নিজে clean এবং শুধু প্রত্যাশিত টেবিলগুলোই তৈরি করে — কোনো অপ্রাসঙ্গিক টেবিল ড্রপ হয়নি, snapshot diff-এও শুধু আগে থেকে জানা `Drug.Product` navigation fix ছাড়া অন্য কিছু নেই। কিন্তু `dotnet ef database update` চালাতে গিয়ে একটা pre-existing, আমার এই কাজের সাথে সম্পর্কহীন সমস্যা ধরা পড়েছে।

**সমস্যা:** স্থানীয় dev database (`HMSDb3`)-এর `__EFMigrationsHistory` টেবিলে `20260727070000_BackfillPublishedDrugItemType` পর্যন্ত সব migration আছে, কিন্তু তার আগের দুটো — `20260727035216_InitialSquashed` ও `20260727040321_SeedAllMasterData` — history-তে নেই, যদিও এই DB-তে তাদের টার্গেট টেবিলগুলো (যেমন `acare_beneficiary_banks`) ইতিমধ্যেই বিদ্যমান। এগুলো সম্ভবত 2026-07-27 তারিখে যোগ করা "squash" migration — নতুন/fresh database-এর জন্য পুরনো ইতিহাসকে একটাতে গুটিয়ে রাখা, কিন্তু এই আগে-থেকে-চলা dev DB-তে সেগুলো apply করার দরকার ছিল না। `dotnet ef database update` migration ক্রম অনুযায়ী প্রথমে এই দুটো চালাতে গিয়ে "table already exists" এরর দিচ্ছে — আমার নতুন migration পর্যন্ত পৌঁছাতেই পারছে না।

**প্রস্তাবিত সমাধান:** `__EFMigrationsHistory` টেবিলে `InitialSquashed` ও `SeedAllMasterData`-এর জন্য দুটো row সরাসরি insert করা (তাদের `Up()` না চালিয়ে, শুধু "applied" হিসেবে চিহ্নিত করা) — কারণ তাদের টার্গেট schema এমনিতেই বিদ্যমান। এটা standard EF technique squash-migration সমস্যার জন্য, কিন্তু এটা shared dev database-এর migration history পরিবর্তন করে, তাই এগোনোর আগে আপনার অনুমতি চাইছি।
