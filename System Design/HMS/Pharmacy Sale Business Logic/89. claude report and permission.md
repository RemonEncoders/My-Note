Parts A+B বন্ধ করলাম — unused dependency-গুলো যেমন আছে তেমনই থাকল। Phase 6-এর জন্য IMS ledger পড়ে পরিকল্পনা তৈরি করেছি।

**আগের একটি বক্তব্য সংশোধন**: আমি বলেছিলাম "HMS-এ কোনো UoW অন্য area-র repository expose করে না"। এটা ভুল ছিল — [InventoryTransferUnitOfWork.cs](vscode-webview://0tri44ar51et483btke71i178mqksugck1rce8n1q6b1u371eioe/HMS.Repository/Areas/IMS/InventoryTransferUnitOfWork.cs) ঠিক এভাবেই root-level `IItemStockRepository`/`IStockMovementRepository` expose করে। অর্থাৎ Part B বিদ্যমান HMS বিন্যাসেরই অনুলিপি, নতুন কিছু নয়।

## Phase 6 পরিকল্পনা — `PharmacyItemStock` Ledger

### যা পেলাম

IMS ledger-এর নকশা আমাদের জন্য আদর্শ — [`IStockLedgerService`](vscode-webview://0tri44ar51et483btke71i178mqksugck1rce8n1q6b1u371eioe/HMS.Services/Areas/IMS/Contracts/IStockLedgerService.cs) **নিজে কোনো DbContext রাখে না**; caller নিজের UoW + repository পাস করে। ফলে quantity পরিবর্তন, movement row আর caller-এর status update সব এক transaction-এ পড়ে। এটাই আমাদের Phase 6-এ দরকার।

আরও পেলাম: `PharmacyItemStock` এখনো সম্পূর্ণ orphan — **DbSet নেই, EF config নেই, টেবিলও নেই**।

### প্রস্তাবিত কাজ (৬টি ধাপ)

**১. Schema** — `ApplicationDbContext`-এ DbSet + `builder.Entity<PharmacyItemStock>().ToTable("phar_item_stocks")`, আর [`ItemStockConfiguration`](vscode-webview://0tri44ar51et483btke71i178mqksugck1rce8n1q6b1u371eioe/HMS.Repository/Configurations/StockMovementConfiguration.cs#L31-L38)-এর হুবহু নকলে একটি **filtered unique index** — এটা ছাড়া ledger-এর insert-race retry কাজ করবে না। + migration।

**২. `IPharmacyItemStockRepository` + impl** — `FindByMatchAsync` / `IncreaseQuantityAsync` / `DecreaseQuantityAsync`, তিনটিই `ExecuteUpdateAsync`, insufficient-stock guard একই WHERE-clause-এ ([ItemStockRepository.cs:56-61](vscode-webview://0tri44ar51et483btke71i178mqksugck1rce8n1q6b1u371eioe/HMS.Repository/ItemStockRepository.cs#L56-L61)-এর নকল)। সাথে FEFO-র জন্য `GetAvailableBatchesAsync`।

**৩. `IPharmacyStockMergeKeyStrategy` + `IPharmacyStockLedgerService` + impl** — `StockLedgerService`-এর গঠন হুবহু: `IncreaseStockAsync`/`DecreaseStockAsync`, caller-এর UoW+repo প্যারামিটারে, DbUpdateException-এ insert-race retry, Exp-mismatch guard, প্রতি পরিবর্তনে ঠিক একটি movement row। **কোনো IMS ফাইলে হাত পড়বে না।**

**৪. `IDrugRepository.GetByProductIdAsync(productId)`** — `SaleItem.ProductId` → `Drug` (locked decision অনুযায়ী সরাসরি `Drug.ProductId` FK query)।

**৫. `IPharmacySaleUnitOfWork`-এ নতুন repository দুটি expose** — ঠিক যেভাবে `InventoryTransferUnitOfWork` করে। এতে Phase 7-এর deduction আপনা থেকেই Confirm transaction-এ ঢুকবে, বর্তমান `IItemStockService`-এর cross-context ত্রুটির পুনরাবৃত্তি হবে না।

**৬. DI registration + build।**

**Phase 6-এ যা করব না**: `PharmacySaleService`-এ কোনো পরিবর্তন (সেটা Phase 7), UOM validation, FormularyStatus guard, UI — সবই Phase 7।
