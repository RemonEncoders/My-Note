নির্দিষ্টভাবে খুঁজে দেখলাম — পুরো `HMS.Entities`-এ `GeneralConfigId` FK-যুক্ত কোনো entity-তে GL রেফারেন্স নেই, এবং "PaymentType + Gl" প্যাটার্নের কোনো entity-ও নেই। **নিশ্চিতভাবে বলা যায়: "Payment Type (GeneralConfig) → GL Account" ম্যাপ করার কোনো existing mechanism HMS-এ নেই।**

`GeneralConfig` entity নিজেই যাচাই করে দেখলাম (`ConfigKey, ConfigValue, StatusFlag, CompanyId, Company, Cities, CustomerVendors, PurchaseOrders`) — কোনো GL ফিল্ড নেই। `GetAllPaymentTypeByKeyAsync()` শুধু `EnumGeneralConfigKey.PaymentType` দিয়ে filter করা plain list, GL-এর সাথে কোনো সংযোগ নেই।

## সবচেয়ে ছোট Reusable Design (প্রস্তাব, implement করিনি)

**একটাই নতুন junction entity, ঠিক `ValuationClassTransaction`-এর মতো প্যাটার্নে কিন্তু সরলীকৃত (TransactionCode/ValuationClass-এর জটিলতা ছাড়া, যেহেতু এখানে সেগুলো প্রাসঙ্গিক না):**

```csharp
public class PaymentTypeGlMapping : AuditableEntity
{
    public Guid PaymentTypeId { get; set; }   // FK -> GeneralConfig (ConfigKey="PaymentType")
    public GeneralConfig PaymentType { get; set; }
    public Guid GlMasterId { get; set; }
    public GlMaster GlMaster { get; set; }
    public Guid? CompanyId { get; set; }      // MaterialTransactionCode/ValuationClassTransaction-এর মতোই ঐচ্ছিক company-scope
}
```

- Root-level entity (`HMS.Entities`-এ সরাসরি, PHAR-স্কোপড না) — কারণ এটা `GeneralConfig`/`GlMaster`-এর মতোই সাধারণ, cross-module system configuration, শুধু Pharmacy-র জন্য না
- Unique index: `(PaymentTypeId, CompanyId)` — একটা payment type-এর জন্য একটাই GL

**একটা নতুন মেথড, existing `IMaterialGLFindService`-এই যোগ করা** (এটাই ইতিমধ্যে-প্রতিষ্ঠিত "GL resolution" সার্ভিস, একই shape বজায় রেখে):

```csharp
Task<Guid> GetGlIdByPaymentTypeAsync(Guid paymentTypeId);
// impl: সরাসরি PaymentTypeGlMapping-এ FK দিয়ে lookup, কোনো string-matching বা history-scan না
```

**Admin UI**: ছোট একটা CRUD স্ক্রিন (প্রতিটা Payment Type-এর পাশে একটা GL dropdown) — `ValuationClassTransactionController`-এর মতোই প্যাটার্ন, কিন্তু আরও সহজ যেহেতু এখানে কোনো TransactionCode/ValuationClass নেই।

এতে:

- কোনো hardcoded payment-type তালিকা নেই — `GeneralConfig`-ই master
- কোনো string-matching (`Contains("cash")`) নেই — সরাসরি FK lookup
- কোনো transaction-history নির্ভরতা নেই — deterministic, pre-configured mapping
- Pharmacy Sale ও Payment দুটোই একই মেথড ব্যবহার করবে, PHAR-নির্দিষ্ট কোনো নতুন logic ছাড়াই
