# ১. Root Cause #1 (EF Tool Version Mismatch) — ✅ আমি একমত

Claude বলছে:

```text
dotnet-ef CLI = 10.0.2
EF Core Package = 8.0.13
```

এটা অবশ্যই ঠিক করা উচিত।

Microsoft-এর সুপারিশ হলো:

> **`dotnet-ef` tool-এর major version এবং EF Core package-এর major version একই হওয়া উচিত।**

অর্থাৎ আপনার ক্ষেত্রে হওয়া উচিত:

```text
dotnet-ef        8.x
EF Core Package  8.x
```

`10.x` CLI দিয়ে `8.x` Model Snapshot manipulate করলে অপ্রত্যাশিত textual পরিবর্তন বা tooling behavior দেখা যেতে পারে। তাই Claude যে এটাকে একটি Root Cause হিসেবে ধরেছে, সেটা যৌক্তিক।

# ৩. ProductId1 Shadow FK — ✅ এটাও EF Core-এর খুব পরিচিত সমস্যা

এটাই রিপোর্টের সবচেয়ে গুরুত্বপূর্ণ অংশ।

ধরুন Entity আগে ছিল:

```csharp
public Guid ProductId { get; set; }
```

Fluent API:

```csharp
builder.HasOne<Product>()
       .WithMany()
       .HasForeignKey(d => d.ProductId);
```

পরে আপনি যোগ করলেন:

```csharp
public Product Product { get; set; }
```

কিন্তু Fluent API Update করলেন না।

তখন EF ভাবে:

> "আচ্ছা, একটা Navigation আছে, কিন্তু এটা কোন FK ব্যবহার করবে বুঝতে পারছি না।"

তখন EF নিজে Shadow FK বানায়।

যেমন:

```text
ProductId1
```

এটা EF Core-এর খুবই Common Behavior।

---

# Claude-এর Proposed Fix

সে বলছে:

```csharp
builder.HasOne<Product>()

↓

builder.HasOne(d => d.Product)
```

এবং Existing FK:

```csharp
.HasForeignKey(d => d.ProductId)
```

ব্যবহার করবে।

**আমি এই Fix-এর সাথে একমত।**

এটা Behavior Change নয়।

এটা শুধু Fluent Configuration-কে Entity-এর সাথে Synchronize করছে।

# আমি Claude-কে কী উত্তর দিতাম?

আমি এভাবে বলতাম:

> তোমার Root Cause Analysis যুক্তিসঙ্গত মনে হচ্ছে।
> 
> EF Tool Version mismatch এবং Snapshot Corruption-এর বিশ্লেষণ গ্রহণযোগ্য।
> 
> `ProductId1` Shadow FK-ও EF Core-এর পরিচিত behavior এবং `Drug.Product` navigation ও Fluent Configuration-এর mismatch থেকেই হওয়ার সম্ভাবনা বেশি।
> 
> তবে পরিবর্তন করার আগে শুধু একবার Verify করো যে `Product` Entity-তেও নতুন কোনো inverse navigation যোগ করা হয়নি। যদি Relationship এখনও `Drug (many) -> Product (one)` এবং `Product`-এ কোনো matching navigation না থাকে, তাহলে `builder.HasOne(d => d.Product).WithMany().HasForeignKey(d => d.ProductId)`-এ Update করো।
> 
> এই Fix Behavior পরিবর্তন করবে না; শুধু Existing Relationship-কে Explicit করবে। এরপর Clean Migration Generate করে আবার Report দিও। অন্য কোনো Module বা Schema Change যেন Migration-এ না আসে।
