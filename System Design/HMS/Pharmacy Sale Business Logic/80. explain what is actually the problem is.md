এটা খুবই গুরুত্বপূর্ণ প্রশ্ন। Claude কেন **Transient → Scoped** করার কথা বলছে, সেটা বুঝতে হলে আগে **DbContext lifetime** বুঝতে হবে।

# সহজ উদাহরণ

ধরুন ব্যাংকে দুইজন cashier একই account-এ একসাথে টাকা তুলতে গেল।

**Transient সমস্যার মতো**

```
Cashier A
দেখল Balance = $100

Cashier B
দেখল Balance = $100

দুজনেই $100 দিল।
```

Account হলো

```
-$100
```

ভুল।

---

**Atomic Database Update করলে**

```
UPDATE Account
SET Balance = Balance - $100
WHERE Balance >= $100
```

প্রথমজন সফল।

দ্বিতীয়জন

```
0 rows updated
```

মানে

```
আগেই টাকা তুলে নেওয়া হয়েছে।
```

এটাই Claude-এর Option 1-এর মূল ধারণা।

## সংক্ষেপে

Claude **Transient → Scoped** করতে বলছে **একটাই কারণে**:

> **Status Update + Journal + Stock যেন একই Database Transaction-এর অংশ হয়।**

কিন্তু যেহেতু সেটা **পুরো HMS application's infrastructure পরিবর্তন করবে**, তাই Pharmacy feature-এর জন্য **targeted DB-level concurrency/idempotency solution (Option 1)** অনেক বেশি নিরাপদ এবং scope-উপযোগী।
