**`IGeneralConfigService.GetAllPaymentTypeByKeyAsync()`** — এটাই আসল, সঠিক "Payment Type" master lookup (Cash/Card/Bank ইত্যাদি, real `ConfigValue` নাম সহ)। ACARE-এর নিজস্ব `PaymentMethodModel.cs` (যেটা admin-রা `PaymentMethod` row তৈরি/এডিট করার জন্য ব্যবহার করে) ঠিক এটাই ব্যবহার করে:

```csharp
var paymentCategoryList = _generalConfigService.GetAllPaymentTypeByKeyAsync().Result;
PaymentCategoryList = new SelectList(paymentCategoryList, "Id", "ConfigValue");
```

**`HMS.Entities.Areas.ACARE.PaymentMethod` কোনো master/lookup টেবিলই না** — এটা একটা **individual payment transaction record** (`PaymentCategoryId` + resolved `PaymentGlId` + amount + card/bank detail সহ), যেটা প্রতিটা প্রকৃত পেমেন্ট প্রসেস হওয়ার সময় তৈরি হয়। এর কোনো স্থায়ী "নাম" নেই কারণ এটা master data-ই না।

**আরেকটা প্রমাণ পেলাম**: `IMS/StockOutModel.cs`-এ ঠিক একই `PaymentMethodList = new SelectList(..., "Id", "Name")` লাইন **already commented out** আছে — মানে অন্য কেউ আগেই এই একই সমস্যায় পড়ে সেটা কাজ না করায় বাদ দিয়ে রেখেছে, ঠিক করেনি। এটা VitalityCash থেকে transfer হওয়া একটা **already-existing, pre-existing latent bug** — এই ফিচারের নতুন কিছু না, কিন্তু আমার নতুন View-ই প্রথম যেটা সত্যিই এই dropdown render করার চেষ্টা করল, তাই ধরা পড়ল।

## গভীর সমস্যা: শুধু UI না, GL-resolution mechanism-ও ভুল জায়গায় বাঁধা

`GetValuationClassIdByPaymentMethodAsync(paymentMethodId)` আসলে `PaymentMethod.Id` (একটা **নির্দিষ্ট transaction row**-এর Id) আশা করে, `PaymentCategoryId` (Cash/Card/Bank টাইপ) না। কিন্তু user তো এখনো কোনো transaction করেইনি — সে শুধু "Cash দিয়ে দেব" এটুকু বেছে নিচ্ছে সবে। এটা একটা chicken-and-egg সমস্যা: transaction row তৈরির _আগেই_ তার Id ধরে GL খোঁজা যায় না।

এটা `PharmacySaleService`-এর **আগে থেকে থাকা (VC-থেকে-ট্রান্সফার করা, আমি লিখিনি) কোডেও একই ভুল ধারণা নিয়ে বসে আছে** (`entity.PaymentMethodId.Value` দিয়ে সরাসরি এই মেথড কল করে) — অর্থাৎ এই ডিজাইন-ত্রুটি Sale ও Payment দুটোতেই মূল থেকেই আছে, আমার Phase 3-এর সিদ্ধান্ত না, তবে সেটার ওপর ভিত্তি করেই বানিয়েছিলাম।

**সঠিক সমাধান কাঠামো**: dropdown-এ `GeneralConfig` (Payment Type/Category, `ConfigValue` দিয়ে) দেখাতে হবে, আর posting-এর সময় category → GL resolve করার একটা নতুন mechanism লাগবে (ACARE নিজে `paymentMethods.FirstOrDefault(x => x.PaymentCategoryId == selected)` জাতীয় fragile lookup করে, একটা clean "category→GL" mapping service নেই)।

এটা এখন সত্যিই একটা architecture-level সিদ্ধান্ত — আমি নিজে থেকে ঠিক করছি না। আপনার নির্দেশনা দরকার।
