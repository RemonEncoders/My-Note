নির্দিষ্ট কোড পড়ে ACARE Patient Invoice-এর Payment Method flow পুরোপুরি ট্রেস করেছি (`Add.cshtml` লাইন ৪৭৭-৫০৬, `_CashPayment.cshtml`, `InvoiceModel.cs`-এর journal posting অংশ)। নিচে চারটা প্রশ্নের সঠিক উত্তর — এবং একটা গুরুত্বপূর্ণ tension পেয়েছি যা আপনাকে জানানো দরকার।

## ১. Payment Method dropdown-এর data source কী?

**এটা আসলে dropdown-ই না — এবং কোনো ডাটাবেস-চালিত তালিকাও না।** `Add.cshtml`-এ সরাসরি Razor markup-এ ৫টা hardcoded checkbox আছে:

```html
<input class="form-check-input payTypeChk" type="checkbox" id="chkCash" value="cash" />
<input ... id="chkBank" value="bank" />
<input ... id="chkCard" value="card" />
<input ... id="chkEWallet" value="eWallet" />
<input ... id="chkDue" value="due" />
```

কোনো টেবিল থেকে এই তালিকা আসে না — এটা View-এর কোডেই স্থির (fixed) করা।

## ২. Selection কোন entity-তে save হয়?

কোনো `PaymentMethodId`-জাতীয় FK কোথাও সেভ হয় না। প্রতিটা checkbox টিক দিলে একটা আলাদা partial view (`_CashPayment.cshtml` ইত্যাদি) দেখায়, যেটা **একটা নির্দিষ্ট, hardcoded .NET প্রপার্টিতে** পোস্ট করে: `CashTransaction.Amount`, `BankTransaction.Amount` + `PayorAccountNumber`, `CardTransaction.Amount` + `CardNumber`, ইত্যাদি। "কোনটা সিলেক্ট করা হয়েছে" এই তথ্যটা কোথাও Id হিসেবে জমা থাকে না — এটা implicit, কোন hardcoded sub-object non-null তার ওপর নির্ভর করে।

## ৩. Posting-এর সময় GL কীভাবে resolve হয়?

```csharp
var cashPaymentGlId = paymentMethods
    .FirstOrDefault(x => x.PaymentGl.GlName.Contains("cash", StringComparison.OrdinalIgnoreCase))
    .PaymentGlId;
```

কোনো pre-configured mapping table থেকে না — বরং **আগের যেকোনো `PaymentMethod` transaction-history row-এর GL account-নামে "cash" টেক্সট খোঁজে**, যেটা পেলে সেই GL-ই পুনরায় ব্যবহার করে। কোনো upfront admin-configuration screen নেই এর জন্য।

## ৪. Pharmacy কি ঠিক এই মেকানিজম reuse করতে পারবে?

**এখানে একটা সরাসরি contradiction আছে যেটা আপনাকে জানানো দরকার**: ACARE-এর নিজস্ব মেকানিজমই **হার্ডকোড করা** — ৫টা checkbox View-এর মার্কআপে স্থির, ৫টা প্রপার্টি Model-এ স্থির, কোনো ডাটাবেস-চালিত তালিকা নেই। এটা কোনো dynamic/reusable "payment type master" না যা আমি টেনে আনতে পারি — এটা নিজেই একটা fixed, code-level তালিকা।

তাই **"ACARE-এর সাথে consistent থাকা" এবং "নতুন hardcoded তালিকা না বানানো" — এই দুটো একসাথে সম্ভব না**, কারণ ACARE নিজেই hardcoded পদ্ধতি ব্যবহার করে। বাস্তবে বিকল্প দুটোই:

- **ACARE-এর সাথে consistent** → Pharmacy-তেও Cash/Bank/Card/Due (ইত্যাদি) checkbox hardcode করতে হবে, ঠিক ACARE-এর মতোই
- **সম্পূর্ণ dynamic/database-driven রাখা** → তাহলে ACARE-এর থেকে ভিন্ন পথে যেতে হবে (আগে আলোচিত `MaterialTransactionCode`/`ValuationClassTransaction` path, যেটা সত্যিকারের admin-configurable কিন্তু ACARE নিজে ব্যবহার করে না)

কোন দিকে যেতে চান?
