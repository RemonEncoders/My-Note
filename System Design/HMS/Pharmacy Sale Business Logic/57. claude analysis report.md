গভীর investigation শেষ — এখন সম্পূর্ণ চিত্র পরিষ্কার, দুটো path তুলনা করে দেখিয়ে দিচ্ছি।

## Path A: `PaymentCategory` (GeneralConfig) + `PaymentMethod` (ACARE)

- Admin কোথাও আগে থেকে "Cash → GL X" ম্যাপ করে রাখতে পারে না — `PaymentMethodModel.cs`-এ কোনো "template"/default-config ধারণা নেই, `PaymentMethod` row শুধু **তখনই তৈরি হয় যখন একটা প্রকৃত পেমেন্ট ট্রানজেকশন হয়**
- GL বের করতে হয় fragile string-matching দিয়ে (`GlName.Contains("cash")`), আগে থেকে অন্তত একটা matching transaction row থাকা লাগে
- **কোনো seed data নেই, কোনো clean admin config screen নেই এই path-এর জন্য**

## Path B: `MaterialTransactionCode` + `ValuationClassTransaction` (SCM) — **এটাই ইতিমধ্যে reusable mechanism**

এটাই ঠিক সেই মেকানিজম যা `PharmacySaleService` নিজেই ইতিমধ্যে Revenue ("SRC") ও Discount ("DOSP") GL বের করতে ব্যবহার করছে:

```csharp
GlMasterId = (await _materialGLFindService.GetMaterialTransactionGlIdByCodeAsync("SRC", null)).Item2
```

- **সম্পূর্ণ, কাজ-করা admin config screen আগে থেকেই আছে**: `HMS.Web/Areas/SCM/Controllers/ValuationClassTransactionController.cs` + Model + Views — যেখানে admin একটা Transaction Code (যেমন "SRC")-কে Debit GL + Credit GL-এর সাথে ম্যাপ করে রাখে
- **ইতিমধ্যে seeded, production-quality কনভেনশন**: "SRC"/"DOSP"/"PSH"/"COGS"/"BSX" কোডগুলো `ACARE/SeedModel.cs` ও `ACC/AccSeedModel.cs`-এ সেড করা আছে
- `GetMaterialTransactionGlIdByCodeAsync(code, companyId)` কল করলে `TransactionCodeId` ধরে সরাসরি (GlDr, GlCr) pair রিটার্ন করে — কোনো "আগে থেকে একটা transaction থাকা লাগবে" সমস্যা নেই
- **শুধু "CASH"/"BANK"/"CARD" কোড এখনো seed করা নেই** — কিন্তু মেকানিজমটা নতুন কিছু বানানো ছাড়াই একই admin screen দিয়ে data যোগ করলেই কাজ করবে

## সুপারিশ

**Path B (MaterialTransactionCode/ValuationClassTransaction) ব্যবহার করা উচিত — এটা genuinely reusable, নতুন কোনো mapping layer/service লেখার দরকার নেই।** শুধু:

1. Admin-কে `ValuationClassTransactionController`-এর existing UI দিয়ে "CASH"/"BANK"/"CARD" (ইত্যাদি) transaction code + তাদের GL ম্যাপ সেড করতে হবে (data-entry task, code না)
2. `PharmacySaleService`/`PharmacyCustomerPaymentService`-এ `GetValuationClassIdByPaymentMethodAsync` কল বাদ দিয়ে `GetMaterialTransactionGlIdByCodeAsync(code, null)` ব্যবহার করতে হবে — ঠিক "SRC"/"DOSP"-এর মতোই প্যাটার্নে

**একটা বাকি প্রশ্ন**: dropdown-এ user কোন কোডগুলো (Cash/Bank/Card/Cheque/Mobile ইত্যাদি) বেছে নিতে পারবে তার তালিকা কোথা থেকে আসবে — `MaterialTransactionCode`-এ কোনো category/type ফিল্ড নেই যা "payment-method কোড" বনাম "revenue কোড" আলাদা করে ফিল্টার করতে দেয়। তাই এই তালিকাটা কোডে সরাসরি নির্দিষ্ট (hardcoded enum-এর মতো, যেমন Cash/Bank/Card/Cheque/Mobile Banking) রাখতে হবে, ডাটাবেস থেকে dynamically filter করা যাবে না — এটা কি গ্রহণযোগ্য, নাকি অন্য কোনো approach চান?
