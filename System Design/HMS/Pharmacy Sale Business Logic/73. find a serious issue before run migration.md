
`__EFMigrationsHistory` insert করার আগে verification চালিয়ে দুটো ভিন্ন ফলাফল পেয়েছি — একটা migration সম্পূর্ণ মিলছে, আরেকটাতে সত্যিকারের mismatch আছে।

**`SeedAllMasterData` (schema নয়, শুধু data seed) — সম্পূর্ণ মিলছে, বরং duplicate ঝুঁকি আছে:** DB-তে ইতিমধ্যে `admin` user, `SuperAdmin` role, `BDT` currency, `Meet Xpert` company, `HMSCOA` chart-of-account সবই বিদ্যমান। এমনকি `sys_general_configs`-এ Country data (`Bangladesh` ২ বার!) ইতিমধ্যে duplicate অবস্থায় আছে — অর্থাৎ এই seed data আসল ইতিহাসে (squash-এর আগের migration নামে) ইতিমধ্যে চলে গেছে। এটাকে না চালিয়ে শুধু history-তে mark করাই সঠিক — বরং এখন চালালে duplicate/constraint-violation তৈরি হতো।

**`InitialSquashed` (schema) — mismatch পাওয়া গেছে:** এই migration ১০টা Cafe Management module টেবিল তৈরি করে (`cafe_bills`, `cafe_orders`, `cafe_categories`, `cafe_menu_items`, `cafe_outlets`, `cafe_bill_payments`, `cafe_day_closes`, `cafe_menu_item_ingredients`, `cafe_order_items`, `cafe_wastage_logs`), কিন্তু বাকি ৪০৩টা টেবিল DB-তে থাকলেও এই ১০টা `HMSDb3`-এ **নেই**। বাকি সব (৪০৩টা) টেবিল হুবহু মিলছে — শুধু Cafe module-এর অংশটাই বাদ পড়েছে, সম্ভবত সাম্প্রতিক Cafe Management PR (#844, দুই দিন আগে merge হয়েছে) merge হওয়ার সময় এই dev DB-তে তার migration কখনো apply হয়নি
