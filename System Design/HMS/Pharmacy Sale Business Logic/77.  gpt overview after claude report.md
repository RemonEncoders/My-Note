দুটি সমস্যার গুরুত্ব আলাদা করে দেখি।

### ১. Non-atomic commit — এটি অবশ্যই ঠিক করা উচিত

Claude যে scenario দিয়েছে:

```
Status = Final  ✔
Journal = নেই ✘
```

এটা accounting system-এর জন্য গ্রহণযোগ্য নয়।

এটা হওয়ার কারণ:

```
Save Status
    ↓
SaveChanges()

Post Journal
    ↓
Exception
```

যদি দ্বিতীয় ধাপে exception হয়, প্রথম SaveChanges() rollback হয় না।

এটা classic transaction problem।

সঠিক flow হওয়া উচিত:

```
Begin Transaction
      ↓
Update Status
      ↓
Create Journal
      ↓
SaveChanges
      ↓
Commit

Exception হলে

Rollback
```

এটা অবশ্যই Phase 6-এর আগে ঠিক করা উচিত।

### ২. Idempotency — এটাও গুরুত্বপূর্ণ

তখন একই sale-এর stock দুইবার কমে যাবে।

এটা আরও বড় সমস্যা।
