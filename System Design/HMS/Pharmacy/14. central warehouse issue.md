**এটা আমার কাছে সবচেয়ে বড় Red Flag.** 🚨

যদি সত্যিই System শুধু

```text
Warehouse.Name == "Central Store"
```

দিয়ে Business Logic চালায়, তাহলে আমি এটাকে **Fragile Design** বলব।

---

## কেন এটা Problem?

ধরুন Admin Name Change করল।

```text
Central Store
```

↓

```text
Main Warehouse
```

অথবা

```text
Central Medical Warehouse
```

তখন?

যদি Code এমন হয়:

```csharp
if (warehouse.Name == "Central Store")
{
    ...
}
```

তাহলে পুরো Logic ভেঙে যাবে।

---

## আরও বড় Problem

ধরুন Multi-language Support এলো।

বাংলায় নাম দিল:

```text
কেন্দ্রীয় গুদাম
```

তখন?

অথবা Typo হলো:

```text
Central Stores
```

অথবা

```text
Central warehouse
```

(ছোট-বড় অক্ষরের পার্থক্য)

সব ক্ষেত্রেই Business Logic Fail করতে পারে।

---

# Enterprise ERP-তে কী করা হয়?

Business Logic কখনো Name-এর উপর নির্ভর করে না।

বরং থাকে:

```text
Warehouse

Id

Name

WarehouseType

or

IsCentralWarehouse
```

অথবা

```text
WarehouseModuleMapping
```

---

# এখন আপনার Project-এর জন্য আমি কী Recommend করব?

আমি Claude-কে বলতাম:

I found another architectural concern.

The current implementation identifies the Central Warehouse only by its name ("Central Store").

I don't think business logic should depend on a warehouse name because names can change, be translated, or contain typos.

Before proceeding further, please analyze whether we should introduce a stable business identifier instead of relying on the warehouse name.

For example:

- `IsCentralWarehouse`
    
- `WarehouseType`
    
- or another stable configuration.
    

If introducing a new property is too invasive for now, please explain the risks of keeping the current name-based implementation and recommend the best long-term solution.

---

## তবে একটা Trade-off আছে

আপনি যদি **এখন Production Release-এর খুব কাছাকাছি** থাকেন,

তাহলে আমি বলব:

- এখন Name-based Logic **অস্থায়ীভাবে রেখে দিন**।
    
- Documentation-এ এটাকে **Technical Debt** হিসেবে লিখে রাখুন।
    
- ভবিষ্যতে Warehouse Refactoring-এর সময় `WarehouseType` বা `IsCentralWarehouse` যোগ করুন।
    

কারণ শুধু এই পরিবর্তনের জন্য এখন Database Schema আবার বদলানো, Seeder Update করা, Migration করা—এসব করলে Scope অনেক বেড়ে যেতে পারে।

---

### আমার Recommendation

- ❌ Name-এর উপর Business Logic দীর্ঘমেয়াদে রাখা উচিত নয়।
    
- ✅ Short-term: চলতে পারে, যদি সবাই জানে এটা Technical Debt।
    
- ✅ Long-term: `WarehouseType` বা `IsCentralWarehouse`-এর মতো একটি স্থায়ী Business Identifier যোগ করা উচিত। এটা ভবিষ্যতের Maintenance এবং Reliability—দুটোর জন্যই অনেক ভালো হবে।
