# RFQ → PO "Create From Tender" — বাগ সমাধানের কেস স্টাডি

**মডিউল:** SCM · Purchase Order from Tender **স্ট্যাক:** ASP.NET Core (Razor) · select2 4.0.5 · jQuery 3.7.1 **ব্রাঞ্চ:** feat/806-ims-and-scm-module · **তারিখ:** 2026-07-26

## TL;DR

- **মূল কারণ:** Entity base constructor `Id = Guid.NewGuid()` বসায়, তাই view-এর `isEdit = Model.Id != Guid.Empty` **সবসময় true**। Create পেজটা edit মোডে রেন্ডার হচ্ছিল — awarded-items হ্যান্ডলারটাই bind হচ্ছিল না।
- **ফিক্স:** edit/create সিদ্ধান্ত এখন কন্ট্রোলারের `ViewBag.IsTenderEdit` থেকে, `Model.Id` থেকে নয়। এক লাইনেই ৪টা লক্ষণ একসাথে ঠিক।

## ১. উপসর্গ

Submission deadline পার হওয়ার পর tender award করে "Create PO from Tender" পেজে গিয়ে PO Category ড্রপডাউন থেকে "Local Goods PO" বাছলেও নিচের awarded-item টেবিলে **Dell Laptop line কখনো আসছিল না**। পেজ লোড হতো, ড্রপডাউন দেখাত, কিন্তু টেবিল খালি।

## ২. তদন্তের ধাপ

- **STEP 1 — সার্ভার-সাইড আগে বাদ দাও:** সরাসরি SQL দিয়ে যাচাই — award ঠিক (`Status=Awarded`, item-এ winner `b1`), RFQ remaining = 8, Dell = goods (`ItemType=2`), "Local Goods PO" category বিদ্যমান। → ডেটা ও লজিক নির্দোষ।
- **STEP 2 — ক্লায়েন্ট-সাইড console diagnostics:** `awardedItems`-এ Dell আছে, `isService=false`, আর `onTenderCategoryChange()` হাতে ডাকলেই `rows: 1`। → ফাংশন ঠিকঠাক row বানায়; শুধু সিলেক্ট করলে auto-trigger হচ্ছে না।
- **STEP 3 — হাইপোথিসিস বাদ:** select2 missing? dual jQuery? double-init? stale view? — প্রতিটাই probe দিয়ে বাদ।
- **STEP 4 — ব্রেকথ্রু:** এক শব্দের চেক `tenderIsEdit` → **true**! অথচ URL হলো CreateFromTender (create)।
- **STEP 5 — কোডে root cause:** view-তে `isEdit = Model.Id != Guid.Empty`, কিন্তু `Entity.cs:13`-এ base ctor `Id`-তে নতুন Guid বসায় → `isEdit` সবসময় true।

## ৩. যেসব হাইপোথিসিস বাদ পড়ল

> আসল শিক্ষা: **select2-এর "change ফায়ার হচ্ছে না" ছিল red herring।** ইভেন্ট ফায়ার হচ্ছিল না কারণ হ্যান্ডলারটাই `if(!tenderIsEdit)`-এর কারণে কখনো bind হয়নি।

## ৪. আসল কারণ — একটা ভুল অনুমান, চারটা লক্ষণ

```csharp
// HMS.Entities/Core/Entity.cs:11-14
public Entity() {
    this.Id = Guid.NewGuid();   // → Model.Id কখনো Guid.Empty নয়
}

// CreateFromTender.cshtml (আগে)
var isEdit = Model.Id != Guid.Empty;   // → সবসময় true !
```

`isEdit` ভুলভাবে true হওয়ায় create পেজ edit ধরে নিচ্ছিল, ফলে একসাথে:

1. awarded-items হ্যান্ডলার `if(!tenderIsEdit)`-এ আটকে **bind হয়নি** → টেবিল খালি;
2. PO Category-তে `pointer-events:none` বসছিল (native করার পর dropdown খুলছিল না);
3. form ভুলভাবে `EditFromTender`-এ পোস্ট হতো;
4. title/hint ভুল দেখাত।

## ৬. শেখার বিষয়

1. **উপসর্গ নয়, root cause খোঁজো।** select2-এর ইভেন্ট নিয়ে অনেক সময় গেল, অথচ আসল কারণ ছিল binding attach না হওয়া। "কেন ফায়ার হচ্ছে না" নয়, "হ্যান্ডলার আদৌ বসেছে কি না" — এটাই প্রশ্ন ছিল।
2. **Base ctor id বসালে `Model.Id` দিয়ে edit ডিটেক্ট কোরো না।** এই কোডবেসের যেকোনো "new vs existing" চেক explicit signal (ViewBag/flag) থেকে হওয়া উচিত — একই ফাঁদ অন্য পেজেও থাকতে পারে।
3. **সার্ভার আগে, ক্লায়েন্ট পরে।** SQL দিয়ে ডেটা/লজিক নির্দোষ প্রমাণ করে ফেলায় খোঁজ সরাসরি ক্লায়েন্ট-সাইডে সংকুচিত হলো।
4. **State জমিয়ে পরীক্ষা করো।** ম্যানুয়াল "মাউস সিলেক্ট" রিপোর্ট অনির্ভরযোগ্য — ইভেন্ট একটা `window.__log` array-তে জমিয়ে পরে পড়াই বেশি নিশ্চিত।
