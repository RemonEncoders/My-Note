খুব গুরুত্বপূর্ণ প্রশ্ন। `systemctl` Linux-এর সবচেয়ে বেশি ব্যবহৃত Administration Command-গুলোর একটি।

## `systemctl` কী?

`systemctl` হলো **systemd**-এর Control Command।

**systemd** হলো Linux-এর **Service Manager** বা **Init System**।

এটি Background-এ চলা Service-গুলোকে Start, Stop, Restart এবং Manage করে।

ভাবুন Windows-এ যেমন **Services (services.msc)** আছে, Linux-এ `systemctl` অনেকটা সেই কাজ করে।

---

# কখন `systemctl` ব্যবহার করবেন?

যখন আপনি **Service** নিয়ে কাজ করবেন।

যেমন:

- Web Server (Apache, Nginx)
    
- Database (MySQL, PostgreSQL)
    
- SSH Server
    
- Docker
    
- Cron
    
- Network Service

# সাধারণ Command

## ১. Service Start করা

```bash
sudo systemctl start nginx
```

মানে

> Nginx Service চালু করো।

---

## ২. Service Stop করা

```bash
sudo systemctl stop nginx
```

মানে

> Nginx বন্ধ করো।

---

## ৩. Restart

```bash
sudo systemctl restart nginx
```

যখন Configuration Change করেছেন।

উদাহরণ:

```text
		nginx.conf Edit করেছেন
		
		↓
		
		Restart করবেন
		
		↓
		
		sudo systemctl restart nginx
```

---

## ৪. Reload

```bash
sudo systemctl reload nginx
```

Reload মানে

Configuration নতুন করে পড়বে

কিন্তু পুরো Service বন্ধ হবে না।

---

## ৫. Status দেখা

```bash
sudo systemctl status nginx
```

Output হতে পারে

```text
Active: active (running)
```

অথবা

```text
Active: inactive
```

---

## ৬. Boot-এর সময় Automatically চালু হবে?

Enable করুন

```bash
sudo systemctl enable nginx
```

মানে

Computer চালু হলেই Nginx চালু হবে।

---

Disable

```bash
sudo systemctl disable nginx
```

Boot-এর সময় আর চালু হবে না।

# `systemctl` বনাম `kill`

ধরুন

```
nginx
```

চলছে।

### Method 1

```bash
kill 2456
```

এতে

- Process শেষ হয়ে যাবে।
    
- কিন্তু Service Manager বুঝবে Service মারা গেছে।
    
- Configuration অনুযায়ী আবার চালু হতেও পারে।
    
- এটি Service Manage করার সঠিক উপায় নয়।
    

---

### Method 2

```bash
sudo systemctl stop nginx
```

এটি

- সুন্দরভাবে (gracefully) Service বন্ধ করবে।
    
- Resource পরিষ্কার করবে।
    
- Log Update করবে।
    

এটাই সঠিক পদ্ধতি।

# `systemctl` বনাম সাধারণ Command

যদি আপনি চালান

```bash
python app.py
```

তাহলে এটি একটি সাধারণ Program।

এটি Start করেছেন

```bash
python app.py
```

Stop

```bash
Ctrl + C
```

Restart

```bash
python app.py
```

এখানে `systemctl` ব্যবহার করবেন না।

# আপনার WSL-এর ক্ষেত্রে

আপনার Ubuntu WSL-এ `systemd` সক্রিয় আছে (এটি আপনার আগের `top` আউটপুটে `systemd` Process দেখে বোঝা যাচ্ছে)। তাই `systemctl` কাজ করবে **যদি সেই Software একটি systemd Service হিসেবে Install করা থাকে**।

উদাহরণস্বরূপ:

```bash
sudo systemctl status cron
sudo systemctl restart cron
```

কাজ করতে পারে।

কিন্তু

```bash
nano file.txt
vim file.txt
ls
cat
top
```

এগুলোর জন্য `systemctl` কখনো ব্যবহার করা হয় না, কারণ এগুলো **Service নয়**, এগুলো সাধারণ Command।

## সহজে মনে রাখার নিয়ম

|আপনি কী চালিয়েছেন?|কী দিয়ে Manage করবেন?|
|---|---|
|`python app.py`|একই Command আবার চালান বা `Ctrl + C` দিয়ে বন্ধ করুন|
|`top`|`q` বা `Ctrl + C`|
|`vim`|`:q`, `:wq`, `:q!`|
|`nginx`, `mysql`, `docker`, `ssh`, `cron` (Service)|`systemctl start/stop/restart/status`|

**একটি সহজ সূত্র:**

> **যদি কোনো Program Background-এ অপারেটিং সিস্টেমের Service হিসেবে চলে এবং Boot-এর সময় স্বয়ংক্রিয়ভাবে শুরু হতে পারে, তাহলে সেটি সাধারণত `systemctl` দিয়ে পরিচালনা করা হয়।**  
> **যদি আপনি নিজে Terminal থেকে কোনো Command চালান (`python`, `node`, `top`, `vim`, `cat` ইত্যাদি), তাহলে সেটি `systemctl` দিয়ে নয়, সেই Command-এর নিজস্ব পদ্ধতিতে নিয়ন্ত্রণ করবেন।**
